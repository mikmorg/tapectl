# Design-doc errata: how to read tapectl-design-v4_0.md now

`tapectl-design-v4_0.md` remains the implementation reference for everything not
listed here, **read together with `CONTEXT.md` (vocabulary), `docs/adr/`
(decisions), and, for the on-tape format and the write session, Layout Version 3's
normative set** (tapectl 2.0.0; ADR-0014, which gathers ADR-0012 items 239 onward), in
authority order: `docs/design/volume-format-v3.md` (the byte format), the "Layout 3"
section of `docs/design/layout-session.md` (the write session), ADR-0012 items 239 onward
(a later item amends an earlier one), then `docs/design/v3-implementation-plan.md` (the
build plan). Layout 2's texts (`docs/design/volume-format-v2.md`,
`docs/design/v2-open-questions.md`, `docs/design/v2-implementation-plan.md`, and the
Layout 2 sections of `layout-session.md` that its "Layout 3" section replaces) are
history: they describe the tapes tapectl 1.x wrote, and 2.0.0 neither reads nor writes
Layout 2 (item 242). Where texts disagree, that set, the ADRs and the verdicts recorded
on closed renovation tickets take precedence. A migration number in a row below is 1.x's:
2.0.0 has one baseline schema, `src/db/migrations/001_baseline.sql`, in place of the 41
migrations (item 258(b); `volume-format-v3.md` Appendix A). This file is the complete
list of known divergences as of 2026-11-24 (ADR-0012 through item 309, and Layout
Version 3); it is maintenance-light by design, and a full v5 rewrite is deliberately
deferred.

Status meanings: **Rejected** — the design's mechanism will never be built.
**Superseded** — replaced by a newer decision. **Recast** — the design's intent
survives but its mechanism is restructured. **Resolved** — the design
self-conflicted; one side won. **Extended** — still true, with new concepts
layered on. **History** — a Layout 2 or 1.x mechanism that tapectl 2.0.0 no longer
has; the row is kept as its record, and says what replaced it, if anything did.

Until 1.6.0 a real EOT was a **clean abort to an unsealed tape**, and the pre-flight capacity gate (#28) was the sole capacity defense. Since 1.6.0 the drive's **early warning** ends the tape with a **short seal**: the slice in flight finishes, and a seal at K+1 states `ended_after = K` (`volume-format-v3.md` §5.2, W1-W9, carried from Layout 2 word for word). In Layout 3 the short seal is part of the layout, and **every unit continues** (item 288; §5.1, §5.3): a staging wholly at or before K is a copy (`completed`), one that K divides is a **range** whose later slices are written first on the next cartridge, and one with no slice at or before K has no write row on that volume. 1.x's `cut` unit, written again whole on the next cartridge (items 9, 99, 112), is gone with Layout 2. The **hard end** inside a slice or a seal, a refused filemark, and an early warning before the first data slice are still the clean abort to an unsealed tape (W6). `writes.eot_recovery` and `writes.sacrificed_slice_id`, inert in 1.x, are not in 2.0.0's baseline schema (item 295). The config `manifest_reserve` collapses to the ENOSPC buffer. |
| §2.8 — Capacity Model | **Recast** | ADR-0010 | Layer 1 ("static default", `nominal_capacity × usable_capacity_factor` from config) no longer reads config for the capacity figure: capacity is a function of the **medium's generation**, overridden by the cartridge row and, for virtual drives only, by the drive's `capacity_override`. It is decided once at `volume init` and stored in `volumes.capacity_bytes`; every later gate reads that row, never config. Layers 2 (MAM) and 3 (ENOSPC) are unchanged, and MAM stays informational. `manifest_reserve` was already gone (row above); `volume calibrate` was never built. The factor itself is now the **fill ceiling**, `fill_ceiling` (default 0.97, was `usable_capacity_factor` at 0.92; ADR-0012 2026-10-06, #391), and `stage create`/`collection plan` refuse a unit bigger than one tape (#395), unless the unit allows spanning: from 1.7.0 such a unit is refused only when it is larger than the staging area (ADR-0012 items 85 and 94; the Appendix A row below). |

| §2.17 — `--copies N` location distinctness | **Recast** | ADR-0004, ADR-0012 (2026-10-07 item 26), #144 | The design says multi-copy writing "ensures copies don't share volumes". `collection run` writes one copy per run, and each further copy is a `volume write` of the same staged data. A destination at a location that already holds a copy of a version being written (a tape shelved there, or a warehouse deposit) gets a **warning** naming it and is written, because ADR-0004 keeps location policy advisory. | §6 — dar invocation example (`--hash sha256 -am --acl --fsa-scope linux_extX`) | **Rejected (mechanism)**; **History** since 2.0.0 | issues #50/#51 re-triage, 2026-07-29/30, verified against installed dar 2.7.13; ADR-0012 items 241, 253, 296 | **tapectl 2.0.0 has no dar** (item 241): GNU tar writes the stream, with the command line of `volume-format-v3.md` §3.1 (the dar row below). What follows is 1.x's record. Three of the four flags in the example are wrong. `--acl` is not a dar option at all: `dar --acl` → `dar: unrecognized option '--acl'`. `--hash sha256` is rejected: dar's `--hash` takes only md5/sha1/sha512/whirlpool/sha3/blake2s, so `dar -c ... --hash sha256` → `Parse error: Unknown parameter given to --hash option: sha256`. `-am` is `--alter=mask`, a mask-*ordering* toggle unrelated to EAs/ACLs — it does not carry ACLs by itself. On Linux, dar carries ACLs as Extended Attributes whenever EA support is compiled in (it is), so ACL data rides ordinary EA carriage, not `-am`/`--acl`. tapectl never implemented `--acl` or `--hash sha256` (there was nothing valid to implement); dar's per-slice `--hash`/`-3` hashing was dropped from `src/dar/create.rs` as unread, wasted I/O — tapectl's own `sha256_plain`/`sha256_encrypted` are the real integrity mechanism.
