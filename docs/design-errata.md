# Design-doc errata: how to read tapectl-design-v4_0.md now

`tapectl-design-v4_0.md` remains the implementation reference for everything not
listed here, **read together with `CONTEXT.md` (vocabulary), `docs/adr/`
(decisions), and — for the on-tape format and write session — the two normative
design notes `docs/design/volume-format-v2.md` (byte format, governed by
ADR-0007) and `docs/design/layout-session.md` (state machine)**. Where they
disagree, the ADRs and normative notes and the verdicts recorded on closed
renovation tickets take precedence. This file is the complete list of known
divergences as of 2026-09-29 (the pre-production rulings, ADR-0012, through its
2026-09-29 amendment); it is maintenance-light
by design — a full v5 rewrite is deliberately deferred until after phase 1
stabilizes the Layout/Session model.

Status meanings: **Rejected** — the design's mechanism will never be built.
**Superseded** — replaced by a newer decision. **Recast** — the design's intent
survives but its mechanism is restructured. **Resolved** — the design
self-conflicted; one side won. **Extended** — still true, with new concepts
layered on.

| Design section | Status | Authority | What changed |
|---|---|---|---|
| Appendix D — Tape append | **Rejected** | ADR-0003 | Sealed volumes are immutable; append is rejected, not deferred. `volume write` refuses non-blank tapes (#27). Resuming an *interrupted, never-sealed* session is not append and remains allowed. |
| §5 CLI — `volume append` | **Rejected** | ADR-0003, #27 | Never implemented; the read-ID-thunk-and-refuse behavior replaces it. |
| §8.1–§8.8 + §2.6 — Volume file formats & zone list | **Superseded** | ADR-0007; `volume-format-v2.md` | The whole on-tape format is redefined as Layout Version 2: a plaintext **front index** (File 3) with per-file position/type/size + ciphertext hashes, **envelopes before slices**, and a trailing plaintext **seal marker**. The v1 mid-tape mini-index and the "8/10-file" labels are gone. `volume-format-v2.md` is authoritative for the bytes. |
| §2.9 + Appendix C — End-of-tape recovery | **Rejected** | ADR-0007, #26 | The three-layer salvage (overwrite-incomplete, sacrifice-last-slice) is deleted, not recast. A real EOT is a **clean abort to an unsealed tape**; the pre-flight capacity gate (#28) is the sole capacity defense. `writes.eot_recovery` and `writes.sacrificed_slice_id` become inert schema reserve (dead columns, never written); the config `manifest_reserve` collapses to the ENOSPC buffer. |
| §2.8 — Capacity Model | **Recast** | ADR-0010 | Layer 1 ("static default", `nominal_capacity × usable_capacity_factor` from config) no longer reads config for the capacity figure: capacity is a function of the **medium's generation**, overridden by the cartridge row and, for virtual drives only, by the drive's `capacity_override`. It is decided once at `volume init` and stored in `volumes.capacity_bytes`; every later gate reads that row, never config. Layers 2 (MAM) and 3 (ENOSPC) are unchanged, and MAM stays informational. `manifest_reserve` was already gone (row above); `volume calibrate` was never built. The factor itself is now the **fill ceiling**, `fill_ceiling` (default 0.97, was `usable_capacity_factor` at 0.92; ADR-0012 2026-10-06, #391), and `stage create`/`collection plan` refuse a unit bigger than one tape (#395). |
| §2.5 — Physical Cartridges vs. Logical Volumes | **Extended** | ADR-0010 | Still true, with the binding made real. "When a cartridge is registered, tapectl reads MAM data" was never built — `cartridge register` takes what you type. **`volume init` now does the binding**: it matches the MAM medium serial to `cartridges.serial_number`; failing that it binds the `--cartridge` you name (and records the serial on that row, once); failing that it auto-registers a cartridge whose barcode *is* the medium serial, a placeholder until `cartridge relabel`. With no readable serial, `--cartridge` is required (ADR-0012) — the serial is the identity, the barcode a label. The `cartridge_volumes` join and the retire → `pending_erase` hand-off the section describes existed only in tests until then, because no production path knew which cartridge it was writing. |
| §2.8 + §5 — `volume calibrate` | **Rejected** | ADR-0012, #145 | Documented with a worked example; never built, and now deliberately not. The capacity model it was meant to refine has the generation table, the cartridge row, MAM (informational) and the ENOSPC buffer under a conservative `usable_capacity_factor` (now `fill_ceiling`, #391), so a measured per-drive overhead constant buys accuracy, not safety. The one real uncertainty — whether MAM's maximum-capacity attribute is MiB or MB — is settled by writing an expendable cartridge to end-of-tape in the pre-production rehearsal, not by a command. |
| §2.5 — cartridge status set (`available`/`in_use`/`pending_erase`/`retired_permanent`/`offsite`) | **Superseded** | ADR-0011, ADR-0012 | Four states; `offsite` is gone from the CHECK (migration 012) because a cartridge's place is its `location_id`, moved with `cartridge move`/`volume move` and inherited by a bound volume at init. `retired_permanent` is written by `cartridge retire` (tiered under ADR-0008) and reversed by `cartridge unretire`; `mark-erased` says the bytes are gone, not that the retirement was a mistake. |
| §7 — Configuration, the `[[backends.lto]]` example (`media_type`, `nominal_capacity`, `block_size`, `hardware_compression`, `manifest_reserve`) | **Superseded** | ADR-0010, ADR-0012 | A drive declares `generation` (and, for virtual drives only, `capacity_override`); every listed key is refused *by name* at load, so a config copied from the design doc is rejected outright rather than misread. Unknown keys are errors in every section, and closed-set values are validated at load (ADR-0012). |
| §5 — `config set` / `add` / `remove` | **Deferred** | #143 | The CLI lists five `config` subcommands; only `show` and `check` exist. `backend add` covers the one block an operator must add without hand-editing TOML. General single-key editing remains hand-edit plus `config check`. |
| §2.17 — `--policy-aware` bin packing | **Deferred** | #144 | The flag, which would prioritise slices that resolve audit violations, was never built and nothing else claims to do it. |
| §2.17 — `--copies N` location distinctness | **Recast** | ADR-0004, #144 | The design says multi-copy writing "ensures copies don't share volumes"; `collection::batch::execute_batch` writes to the operator-named labels in order and checks nothing. That is consistent once stated correctly: distinctness is **audited after the fact**, never enforced at pack time, because ADR-0004 makes the policy layer advisory. The guarantee belongs to `audit`'s copy and location checks, not to the packer. |
| §2.24 — Signal handling vs §4 — Recovery | **Resolved** | ADR-0002, #25; triage on #17 | The design self-conflicted (§2.24: interrupted resumes; §4: startup converts interrupted→aborted). §2.24 wins: `interrupted` is resumable while the session's Layout stays valid; the startup sweep marks orphaned `in_progress` sessions `interrupted` (crash), never `aborted`. |
| §2.29 — LTO drive access (variable block mode, `MTSETBLK 0`) | **Superseded** | implementation standard; audits #3/#5; #27 doc trail | Fixed 512 KB blocks are the standard everywhere (write path, RESTORE.sh, guide). The ID-thunk instruction bug (`dd bs=64k`) is #29. **Correction 2026-09-10:** hardware compression off (`MTCOMPRESSION 0`) has *already landed* — `TapeStore::open` (`src/store.rs`) calls `disable_compression()` unconditionally on every open of the write path, and the real HP LTO-6 confirmed it (mode page 0x0f `DCE` went 1→0 across a `volume write`; `docs/lto6-session-journal-2026-09-10.md` Phase 4). Since 2026-09-13 the key is gone: a config that carries it is refused by name at load (the §7 `[[backends.lto]]` row above), with a message saying that compression is disabled on every open and to delete the line. |

| §2.16 — Encryption & keys | **Extended** | ADR-0005, ADR-0009, #68/#69 | A permanent **escrow recipient** participates in every write and is exempt from `key rotate` (which refuses if it is absent). The Heir Kit replaces the doc's `key export --qr` idea (that flag is superseded; see LOW umbrella #66 rider). **CTO decisions 2026-08-01, recorded in ADR-0009:** #69's deferral covers only the *ceremony* (printing, tamper-evident envelopes, distribution), not the command — `key escrow-kit` is ordinary software and #68 is closed, so it is built and stops at the printed artifact. (b) Pre-escrow tapes: `volume write`/`compact-write` **refuse by default** to seal a reactivated stage set whose recorded `key_fingerprints` lack the current escrow recipient (#115), with an explicit **`--allow-missing-escrow`** override for the one legitimate case — migrating a dying pre-escrow cartridge forward via `read-slices`/`compact-read`. The override is safe to expose on `volume write` because pm-115's `stage create` refuses to stage without escrow, so a set lacking escrow can *only* originate from a copy of an already-sealed pre-escrow volume, never from fresh staging. #125 (audit surfaces such volumes) makes them visible regardless. |

| §2.2 — `.tapectl-unit.toml` example (concrete `compression`/`checksum_mode`) | **Recast** | CTO decision 2026-07-30, #92 | The example shows every policy field with a concrete value, and the implementation matched it: `UnitDotfile` declared them non-`Option` with serde defaults, so a missing key was filled and presented to `policy::resolve` as a real value — which then unconditionally outranked the archive set. Effect: **an archive set's `compression` was silently unreachable for every dotfile-backed unit**, i.e. every unit made by `unit init`. Ratified fix: the dotfile's policy fields become `Option`, are **omitted** from newly-written dotfiles unless the operator sets them explicitly, and absent means *defer upward* — restoring the documented dotfile > archive_set > defaults precedence as a real three-layer resolve instead of a one-layer one. | §6 — dar invocation example (`--hash sha256 -am --acl --fsa-scope linux_extX`) | **Rejected (mechanism)** | issues #50/#51 re-triage, 2026-07-29/30, verified against installed dar 2.7.13 | Three of the four flags in the example are wrong. `--acl` is not a dar option at all: `dar --acl` → `dar: unrecognized option '--acl'`. `--hash sha256` is rejected: dar's `--hash` takes only md5/sha1/sha512/whirlpool/sha3/blake2s, so `dar -c ... --hash sha256` → `Parse error: Unknown parameter given to --hash option: sha256`. `-am` is `--alter=mask`, a mask-*ordering* toggle unrelated to EAs/ACLs — it does not carry ACLs by itself. On Linux, dar carries ACLs as Extended Attributes whenever EA support is compiled in (it is), so ACL data rides ordinary EA carriage, not `-am`/`--acl`. tapectl never implemented `--acl` or `--hash sha256` (there was nothing valid to implement); dar's per-slice `--hash`/`-3` hashing was dropped from `src/dar/create.rs` as unread, wasted I/O — tapectl's own `sha256_plain`/`sha256_encrypted` are the real integrity mechanism. At this re-triage tapectl still passed `-am` (only its doc comment was corrected) and passed no `-u`/`-U` EA-exclusion mask, so EAs and ACLs were archived whatever the config said. **Since #347 (2026-09-29) `-am` is not passed at all, and `preserve_xattrs = false` passes `-u "*"`**, which drops every EA and the ACLs with it — see the #347 row below. |
| §7 / §4 schema — `preserve_acls` config knob and column | **Clarified (no-op made visible)** | CTO decision 2026-07-31, #50 | The knob is documented (§1363) and has an `archive_sets` column, but **dar exposes no independent ACL switch**: on Linux ACLs ride Extended Attributes, so honoring `preserve_acls = false` would require excluding EAs wholesale (`-u`/`-U`) and would therefore also drop every xattr the operator did not ask to lose. When this was ruled, ACLs were preserved unconditionally, so the knob's *intent* was satisfied — it simply could not be independently turned off. **Since #347 ACLs follow `preserve_xattrs`**: kept when it is `true`, dropped with every other EA when it is `false`. `preserve_acls` still cannot act on its own, in either direction. Ratified: **keep the field and the column, and make the no-op visible rather than silent** — `config check` notes that `preserve_acls` is subsumed by `preserve_xattrs`, and since #347 it does so for any layer where the two disagree, whichever way round. Rejected alternatives: honoring it literally (does something the operator did not ask for), and deleting it (contradicts a documented section and breaks existing `config.toml` files). Follows the #92 precedent: surface a dead knob, do not silently delete operator-facing surface. The dead plumbing between `policy::resolve` and `DarCreateParams` was removed as part of #50; the operator-facing surface was not. |
| §5 CLI — `restore unit` / `restore file` overwrite behavior | **Extended** | CTO decision 2026-07-31, #51 | The design never states what a restore does when the destination already holds the file. Measured against dar 2.7.13: under `-Q` dar **silently skips the colliding file and still exits 0**, leaving the stale copy while reporting success — a silent partial restore in the most safety-critical path. The trap for any implementer: the skip is tallied under `inode(s) ignored (excluded by filters)`, while `inode(s) not restored (overwriting policy decision)` — the counter whose name matches the situation — reads **0**; the per-file signal is the stdout line `<path> not restored (user choice)`. Ratified: **detect and fail** — run dar as today, then inspect its report and return an error naming the skipped files. Deliberately not chosen: refusing any non-empty destination (breaks restoring several units into one `--to`, and does not generalize to single-file restore), and `-w` (would newly authorize clobbering operator data the current code never touches). |

Those three are every unit status there is: the fourth, `retired`, was audited by nothing, was never set by any command, and was dropped from the schema by migration 026 (#362, row below). |

| §8 / on-tape envelope — `MANIFEST.toml`'s `layout_version` | **Deleted** | CTO decision 2026-09-11, #134 | The tenant/operator envelope manifest emitted `layout_version = 1` on every volume, including v2 tapes. It is a v1-era constant from the Milestones 0-4 commit (`a7507b4`) that the v2 flip (`1a8f429`, T8) never touched, and **nothing has ever read it** — every `layout_version` reader in `src/volume/format.rs` parses the ID thunk, front index or seal marker, all of which say `2`. `volume-format-v2.md` never specifies the field for the envelope at all, and states that no production `layout_version = 1` tape is expected to exist, which made the envelope's `1` doubly misleading: an heir comparing the envelope against File 0 would conclude the tape was internally inconsistent when it is not. Ratified: **delete the field**, do not bump it to 2. Bumping would leave tapes already written disagreeing with newer ones for no reader's benefit; renaming it `manifest_version` would preserve a version nobody consults. Same reasoning as `meta.schema_version` (#61) — a version field with no reader cannot be kept honest and should not exist. Tapes already written keep saying `1`; the system guide tells an heir the tape's own zones are authoritative. |
| §2.20 / escrow coverage query | **Extended** | coordinator decision 2026-09-11 (architecture review C1) | The SQL behind "escrow coverage of a stage set" — which stage sets, on which volumes, with what recorded recipient list and origin — was hand-written in four places (`audit`'s `escrow_coverage` check, `report copies`' `escrow_gaps_by_unit`, `catalog locate`, and the `volume write` pre-flight's `stage_sets_lacking_escrow`) and had already drifted apart: different reason strings for the same verdict. Volume filter is `policy::coverage::in_service`, not `eligible` and not an ad-hoc status list — escrow asks "does the current key open bytes on media we still account for", a different question from ADR-0004 durability, and the ad-hoc list let `quarantined` volumes through undetected. | §6 / §2.26 / §7 — `preserve_xattrs` and `preserve_fsa` (the dar flags behind them) | **Recast** | #347 (found by the 2026-09-28 documentation pass), 2026-09-29 | The design maps `preserve_xattrs` to `-am` and `preserve_fsa` to `--fsa-scope`. Until #347 neither key changed anything. `-am` is mask ordering (§6 row above), so extended attributes were archived whether `preserve_xattrs` was `true` or `false`. `preserve_fsa = false` passed no `--fsa-scope`, which dar reads as every FSA family, so chattr flags were archived either way too. Now every `dar -c` passes **no `-am`**. `preserve_xattrs = false` passes **`-u "*"`**, which drops every extended attribute and, with them, the POSIX ACLs Linux stores as extended attributes (`system.posix_acl_*`); `true` passes nothing, and dar keeps them. `preserve_fsa` passes `--fsa-scope extX` when `true` and **`--fsa-scope none`** when `false`. Both default to `true`, so a default archive's content is unchanged; its recorded dar command loses only `-am`. `preserve_acls` still has no effect of its own (§7 / §4 schema row above). `dirty_on_metadata_change` (§7 `[defaults]`) is accepted and stored but not consumed — dirty detection compares path, size and modification time only — and `config check` now says so whenever it is `true`. |
| §2.22 / §7 `[defaults]` — `min_copies_for_tape_only`, `min_locations_for_tape_only` | **Superseded** (renamed) | ADR-0012 2026-09-29 amendment item 4, #348 | The keys are now `[defaults] min_copies` and `[defaults] min_locations`, with the same meaning and the same defaults (2 and 2); `init` writes the new names. | §4 schema / §2.3 Phase 1-2 — `manifests`, `manifest_entries`, and the `files`/status indexes | **Superseded** (removed) | #372, #373 (2026-09-30 structural review); migration 027 | The design keeps a per-snapshot manifest (`manifests` + `manifest_entries`: path, size, mtime, sha256, mode, uid, gid, user and group names) beside `files`, backfills sha256 into both on first stage, and deletes both at purge.
