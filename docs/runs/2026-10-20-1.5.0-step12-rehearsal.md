## #444, run straight after: the verified-erase proof and the chip's counters

On the same cartridge, the same binary, by an agent on home2 as the operator's login, in two
throwaway homes under `~/.cache/tapectl/p444-20261020T024320Z/` (logs `run.log`, `measure.log`),

**The verified-erase proof holds on the HP drive. 0 failed:**
- Home c ran `cartridge erase --confirm-label VOL-A`. It read the tape back ("File 0 EMPTY; chip serial

- Home d has no erase record. Its `volume init` refused with exit 2: "File 0 is EMPTY … re-run with

**Reading.** The counter moves in lumps that do not track the data. 10 MiB of data added 2, and a
read-only pass added 2, so some of it arrives late. It does not floor in the case the proof needs,
though. Every write that leaves File 0 EMPTY moved it by at least 7 MiB: a short erase, and a lone
filemark at the beginning of the tape (`mt weof`, what the lifecycle suite does). Those are the
writes the proof exists to catch between this catalog's erase and its init. A write that leaves data
at the beginning makes File 0 read as something, and the proof is not consulted then. So the
comparison catches what it must, and no tightening is needed.

A late tick can void a genuine proof. That fails closed, asking for `--force`. It did not happen
here: erase and init 11 s apart read the same figure.
