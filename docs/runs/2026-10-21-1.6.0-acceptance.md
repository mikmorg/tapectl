# 2026-10-21: the 1.6.0 short-seal acceptance run on home2

`scripts/short-seal-acceptance.sh` on the real drive, on the CTO's go-ahead (ADR-0012 items 110,
114, 115 and 117). It ran from 2026-10-21 14:02:55 to 2026-10-22 05:25:06 UTC and **passed all
seven steps**. The production home, the production binary and every production cartridge were
left alone.

## Conditions

- **Binary:** a debug build of `c9c5877`, `tapectl 1.6.0 (v1.5.0-112-gc9c5877, 2026-10-21)`,
  sha256 `725c177e97e4dc6518f3146c7cf3222e9bada77720ca316015c39a3144090daa`. It was built on
  vm-desk1 and copied to `~/tapectl-1.6.0-c9c5877/` on home2, with that commit's
  `examples/short_seal_filler` and the acceptance script beside it.
- **Drive:** the HP LTO-6 HUJ808A5L4, `/dev/tape/by-id/scsi-HUJ808A5L4-nst` (`/dev/nst0`,
  `/dev/sg13`).
- **Cartridge:** the test cartridge, chip serial **EW7VWMVKF6**, registered at 2.550 TB.
- **Config:** `post_warning_bytes = "99008M"` (item 118), slices of 1 GiB, `min_copies = 1`, in
  a throwaway home (`~/.cache/tapectl/ssa-home-20261021`).
- **Tools:** age v1.3.2 and GNU tar 1.30, with the system's dar.
- **Host:** the operator stopped `tapectl-drive-poll.timer`. homorg paused its timers and
  lcsas-4c stayed quiet for the whole run, and nothing heavy ran on vm-desk1.
- **Run directory:** `~/.cache/tapectl/short-seal/ssa-20261021T140255Z-EW7VWMVKF6`.

**Item 110 is proven on the real drive.** Past the early warning, st refused 846 blocks, and the
writer retried each until the drive took it. The slice in flight (file 2338, 1,074,266,112
bytes on tape) and the short seal were written. The confirm read back 1,075,314,688 bytes past
the warning: that slice and the seal (item 114). No block the drive kept after a refusal showed
up as a duplicate or a gap, and the whole-tape reads in step 4 agree.

| What | Figure |
|---|---|
| The early warning | at 2,502,136,692,736 bytes from BOT, which agrees with the 2026-09-23 fill measurement (2.5020 TB before ENOSPC). Only the slice in flight was written past it, far inside the 99,008 MB `post_warning_bytes` allows |

| RESTORE.sh `--verify` | 2.28 TiB in 6h 8m, about 108 MiB/s. Bound by the CPU: coreutils `sha256sum` used 90% of one core and `dd` 15%, on home2's Xeon L5640, which has no SHA instructions |
| Feed ratio | 0.983, no warning, 0 repositions per 100 MB (page 0x34) |
| Drive error pages | no uncorrected write or read error. TapeAlert (page 0x2E) raised no medium flag |

Two figures need reading with care:

- **The debug build's encryption and decryption are slow.** `stage create` encrypted at about
  3.9 MiB/s: `ssa-b-photos`' 1.5 GiB took 6m 37s. tapectl's restores decrypted at a flat 3.0
  MiB/s: `ssa-b-photos` took 8m 29s, while RESTORE.sh, using the `age` CLI on the same tape and
  through the same `dar --sequential-read` over FIFOs, took 1m 51s.

  Both tapectl paths use the `age` crate's ChaCha20-Poly1305, which is pure Rust and runs
  unoptimised in a debug build. The write and verify went at tape speed because they decrypt
  nothing and hash with ring's assembly. Production runs a release build, so these rates are
  not production's.

  **tapectl's restore rate in a release build has never been measured on the real drive.**
  #488's drive phase measures it with the release research binary. During these restores the
  drive was stopping and starting, for about 10 minutes and on the test cartridge only.
- **The feed ratio is below 1.** Page 0x0c's data bytes (2,549,110,800,384) exceed the native
  tape used from BOP to EOD (2,506,915 MB). That is about 42 GB more than the 2.28 TiB the write
  sent. What that counter includes is not yet known, and it is looked at under #488.

## Afterwards (the operator)

- The cartridge holds SSA-0002 (the cut unit only), owned by the throwaway home. To return it
  to the test pool, run `tapectl --home ~/.cache/tapectl/ssa-home-20261021 volume retire
  SSA-0002`, then `cartridge erase` from the same home.
- Start the drive-poll timer again: `sudo systemctl start tapectl-drive-poll.timer`.
- Then install 1.6.0 by `docs/handoff.md` (g).
