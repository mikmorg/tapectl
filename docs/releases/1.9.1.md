# tapectl 1.9.1: release notes

What changed between `v1.9.0` and 1.9.1, for the person who runs tapectl. The record is
`git log v1.9.0..` on the 1.9.1 tree, #486, and ADR-0012 items 222-234 (ruled 2026-11-09, in a
grilling of the questions 1.9.0 left open). No byte that tapectl writes to tape changed, there is
no catalog migration, and no command or flag spelling was removed, so by the version rule
(item 201) this is a patch, though a large one: the CTO folded the friends' setup into it
(item 232).

## For a new operator with one drive

- **`tapectl setup`, a wizard in the binary** (items 227, 229, 231). Run as your own account, it
  asks one question at a time, with a default for each, and does each step: the home (default
  `~/.tapectl`), a staging directory, the drive (found under `/dev/tape/by-id`, its generation
  read from the drive; identity only, it never opens the tape for I/O), the operator and escrow
  keys (the escrow secret is shown once on the terminal and stored nowhere, as `init` does,
  ADR-0005), two locations (`home`, `offsite`), a first collection, and weekly catalog-backup and
  audit timers as systemd USER units. It never runs anything as root: what needs root
  (`usermod -aG tape`, missing packages, `loginctl enable-linger`) is printed as one block to
  paste. Every answer has a flag, `--yes` takes the defaults, `--dry-run` changes nothing, and a
  second run finishes a first one that stopped. The rehearsal and the drive profile are
  optional; it names them and runs neither.
- **The [Quick start](../quick-start.md)**: installing, a real `setup` transcript, the root
  block, the first two copies.
- **A static binary on every release** (item 230). From this release, each tag `vX.Y.Z` gets a
  GitHub release carrying `tapectl-X.Y.Z-x86_64-linux-musl` and its `SHA256SUMS`, built by CI
  (`.github/workflows/release.yml`). It needs no library from the machine. `cargo install
  --locked --git https://github.com/mikmorg/tapectl` stays the fallback.
- `scripts/first-run.sh` is unchanged and stays the installer for a host run by a service user,
  like home2 (item 228); `docs/install.md` says who reads which.

## Changed behaviour

- **`unit check-integrity`: the modification time decides a size change too** (item 224). A
  file whose size changed and whose mtime moved since the snapshot is CHANGED (an edit, exit 0,
  "unit is dirty: snapshot it"); a size change at the recorded mtime stays SIZE_MISMATCH
  (exit 1). Under 1.9.0 every size change exited 1, so most real edits read as damage. Where the
  snapshot recorded no mtime, a size change stays SIZE_MISMATCH. CHANGED keeps exiting 0
  (item 223).
- **`catalog rebuild --from-volume` gives a cartridge it registers its File 0 label as the
  barcode** (item 226), as `volume init` has since 1.9.0 (item 219). The chip serial stays the
  identity, a cartridge the catalog already holds keeps its barcode, and when another cartridge
  already has that label the new one keeps its serial and the rebuild prints the
  `cartridge relabel` that fixes it. The relabel step after a disaster-recovery rebuild is gone
  from the docs.
- **`status`** suggests `snapshot create --all-pending` when several units are pending.

## New commands and flags

- `tapectl setup` (above).
- **`snapshot create --all-pending`** (item 225): snapshots every active unit that is pending
  (never archived, or dirty), by name; nothing pending is exit 0. It cannot be combined with
  unit names. A unit the scan cannot read is named on stderr and skipped.
- **`key escrow-kit --static-binary FILE`** (item 234, #486). The kit copies the release's
  static build in beside the running program, as `tapectl-X.Y.Z-x86_64-linux-musl`, and the
  cover sheet names it first, with its size and sha256. The file must be a static x86_64 program
  whose `--version` is the running tapectl's. Without the flag, a kit made by a tapectl that is
  not static names the release asset's URL and says to check it against `SHA256SUMS`; a kit made
  by a static tapectl says its copy is the static build.

## JSON changes

Keys added, none renamed or removed:
- `catalog rebuild --json`: `cartridge_label_taken`.
- `key escrow-kit --json`: `program_is_static`, `static_copy` (`path`, `sha256`, `bytes`),
  `static_url`.

## Scripts

  edit to read CHANGED with exit 0.

## Upgrading from 1.9.0 or 1.8.1

Nothing besides `scripts/first-run.sh --upgrade` from a checkout of `v1.9.1`. From 1.8.1 (home2,
which skipped 1.9.0), read [1.9.0's notes](1.9.0.md) first: their removed spellings and changed
defaults apply too, and there is still no migration. Regenerate the
Heir Kit afterwards as usual; to put the static build in it, download
`tapectl-1.9.1-x86_64-linux-musl` and `SHA256SUMS` from the release, check them, and run
`tapectl-op key escrow-kit <dir> --static-binary <file>`.
