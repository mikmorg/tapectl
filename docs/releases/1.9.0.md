# tapectl 1.9.0: release notes

What changed between `v1.8.1` and 1.9.0, for the person who runs tapectl. The record is
`git log v1.8.1..` on the 1.9.0 tree and ADR-0012 items 198-221 (amendment "2026-11-04"), the
CTO's rulings on the CLI review of that day (`docs/audits/2026-11-04-cli-review.md`). No byte
that tapectl writes to tape changed, and there is no catalog migration (item 221). The minor
moves because command and flag spellings are removed: by the version rule as item 201 amends
it, a removed spelling is a minor, like a change to the bytes on tape.

- **Renamed commands and flags lose their old spelling at once** (items 203, 209, 210). An old
  spelling is refused by name and exits 2, so a script that uses one stops rather than doing
  something else. The table is below. The three commands every tape's File 1 prints work for
  good.
- **One copy loop: `volume write L --init --full-confirm --move-to X`** (item 218). The write's
  readback of every file is the tape's first full verify and is recorded as one, so no
  `volume verify --full` follows a write any more; `volume verify --full` is for the periodic
  re-reads `verify_interval_days` asks for. `first-run.sh` step 13 is that loop.
- **Staging is released unit by unit** after each write (item 217): every unit at its copy
  floor is released, and a unit still short of it stays staged.
- **A cartridge's first barcode is its first volume's label** (item 219), so no
  `cartridge relabel` follows a first copy; the chip serial stays the identity.
- **`tapectl status` is the home screen** (item 213): the home and why it was chosen, what is
  running, units by state, tapes due a verify and the next commands.
- **`collection add` and `collection remove`** (item 206), and **`config get`** (item 214).
- **Help, output, JSON and exit codes are made consistent** (items 211, 212): grouped help,
  borderless tables, UTC times, human sizes, real plurals, one JSON shape per command and JSON
  errors under `--json`.
- **The defects the review found are fixed** (item 220), and the scripts batch #511 waited for
  ships inside the release (item 205): the staging diagnosis (item 199), `POST_WARNING_BYTES`
  (item 200), `keepsake` out of `home2.profile` (item 204).
- **Issues this release finishes:** #511.

## Renamed commands and flags

Each spelling on the left is refused, before the command line is parsed and before any home is
opened, however it is reached: as a command, with `--help`, through `tapectl help`, or as a bare
group. The refusal names the new spelling and exits 2; under `--json` it is the JSON error
(below):

```text
error: `tapectl backend add` was renamed in 1.9.0: use `tapectl drive add`
```

| 1.8.1 | 1.9.0 |
|---|---|
| `backend add` (and the `backend` group) | `drive add` (the `drive` group) |
| `staging clean` | `stage clean` |
| `staging status` (and the `staging` group) | `stage list` (the `stage` group) |
| `report pending` | `stage list --owing` |
| `report summary` | `status` |
| `report supersedable` | `report reclaimable` |
| `unit status NAME [--dirty]` | `unit info NAME [--dirty]` |
| `catalog ls` | `catalog list` |
| `export --unit U --to DIR` | `unit export U --to DIR` |
| `import …` | `volume import LABEL …` |
| `volume compact-write --destination L` | `volume compact-write --to L` |
| `volume read-slices --unit U --from L` | `volume read-slices U --from L` |
| `host check --unit U` | `host check --systemd-unit U` |
| `db backup --to FILE` | `db backup PATH` |
| `key escrow-kit --out DIR` | `key escrow-kit DIR` |
| `collection run --collection C` | `collection run C` |

Two edits of `config.toml` are refused the same way, pointing at the commands that check what
they write: `config add collections …` (use `collection add`) and
`config remove 'collections[NAME]'` (use `collection remove`).

**Never renamed:** the three commands every tape's File 1 prints (item 203):
`tapectl init --operator … --escrow-public-key …`,
`tapectl catalog rebuild --from-volume --device … --key …` and
`tapectl restore unit --unit … --device … --to … --key …`. The restore family keeps `--unit`
beside its new positional, since an heir who learned it from File 1 types it on `restore file`
too. The config key `[[backends.lto]]` keeps its name (item 208), and `--dry-run` gains `-n`.

## New commands and flags

- **`collection add NAME ROOT --tenant T [--unit-depth N] [--exclude G]… [--archive-set S]
  [--no-dotfiles]`** (item 206). It refuses a missing, relative or overlapping root, an unknown
  tenant or archive set and a name already configured; checks that the account it runs as (the
  service user under `tapectl-op`) can read the tree and write each unit folder, and prints the
  exact `setfacl` lines when it cannot; then writes the `[[collections]]` table and shows the
  sync's dry run. **`collection remove NAME`** takes the table out and leaves its units
  registered and untouched.
- **`config get KEY`** (item 214): the value in force and where it comes from (`# set in
  <file>`, `# default`, `# derived from device_tape`). A bare key resolves against the schema,
  and with one drive `post_warning_bytes` is that drive's:

  ```text
  backends.lto[lto6].post_warning_bytes = "99008M"  # set in /var/lib/tapectl/.tapectl/config.toml
  ```

  `config set` and `config get` take the same forms; a mistyped key gets a did-you-mean.
- **`status`** (item 213) is the home screen; `report summary` is refused and points to it.
- **`collection run [NAME] --label L --init --move-to X`** (items 210, 220): the run initialises
  the blank cartridge first and moves the tape once it is sealed and confirmed. NAME defaults to
  the only collection configured; one `--label` per run, and a second is a usage error naming
  the rule.
- **`volume init --barcode B`** and **`volume write L --init --barcode B`** (item 219): the
  sticker's text when it is not the label.
- **`volume resume --move-to X`** (item 215): beside `--full-confirm`, it adds to what the
  interrupted write asked; a place other than the one the write recorded is refused naming both.
- **`stage list --owing`** and **`stage list --all`**: the stage sets held in staging with each
  version's copies; `--owing` only the ones still owed a copy; `--all` adds the released and
  failed history (item 207).
- **`snapshot create A B C`**: several units, each reported on its own; one that fails stops
  none after it (item 210).
- **`key list`** without `--tenant` lists every tenant's keys, with a Tenant column.
- **`drive add`** reads the generation from the attached drive's model; `--generation` is needed
  only when the drive is not attached or its model is unknown (item 219).
- **`db backup DIR`** writes `DIR/tapectl-YYYYmmddTHHMMSSZ.db`, the timer's name, and a
  backup never overwrites a file: an existing PATH is refused (OQ20).
- **`volume plan --generation`, `collection plan --generation`**: plans need no drive (item 214).
- **`restore file UNIT PATH`** takes its unit and file in every spelling, `--unit` and `--file`
  included.

## Changed behaviour

**Copies.**
- A write's last lines say what it did and what comes next (item 216):

  ```text
  sealed and confirmed: <N> units, <N> slices, <size>; full readback passed
  next: tapectl volume write <NEW-LABEL> --init --full-confirm --move-to <place>
  ```

  The first line follows `volume "L" write completed`, which is kept word for word. The next
  command names the place a copy target is still short of (`<location>` when only the copy
  floor is), or says `nothing to do`. `collection run` and `volume resume` end the same way.
  The chip's wear figures and a feed ratio that tripped nothing move behind `-v`; a warning that
  reports a problem (LBP unavailable, a tripped feed ratio, a TapeAlert) prints where it did.
- **Staging is released per unit after each write** (item 217, amending #440's all-or-nothing).
  By default a unit is released once it is at its **copy floor** (item 154 stands); every
  `copies_at` target is waited for only under `--keep-staging-for-locations`. The units kept are
  named with why. Twins stay twins: after copy 1 of 2 every unit is still staged.
- **`volume resume` keeps what the interrupted write asked for** (item 215): its
  `--full-confirm` and `--move-to` (and its staging flags) are recorded in the session's
  directory and honoured, and the resume says so. A session written by 1.8.1 resumes as before.
- **The cartridge takes the label** (item 219). A cartridge registered at `volume init`, or one
  still wearing its chip serial as a placeholder (1.8.1 and `cartridge erase` registered those),
  takes `--barcode`, else the volume's label: `cartridge L6-0001 auto-registered from MAM (chip
  serial …; barcode L6-0001, the volume's label)`. A cartridge with a barcode of its own keeps it.
  Every `<CARTRIDGE>` argument takes the barcode or the chip serial (item 208).
- **This catalog's own sealed volume is never offered for erasing** (item 216). `volume init`
  and `write --init` with it still loaded name it as this catalog's live copy and say to eject it
  and load a blank; the erase routes are offered only for a volume the catalog does not hold, or
  holds retired. The `mt` recipe moved to the troubleshooting guide.
- **`volume verify` says when the last full read was** (a write's full confirm counts), then
  reads anyway; it never prompts.
- `drive eject` names the volume on the cartridge and the place it belongs. A move to where the
  tape already is says `is already at "X": nothing changed`. `cartridge erase` prints its facts
  once, before any refusal, and its prompt names whose volume it is.
- `volume not found` suggests the nearest label, ignoring case. `collection run` on a label not
  yet initialised says to initialise it. The ssh warning waits until the label is found.
- The phrases scripts route on are kept word for word: `write completed`, `already carries a
  SEALED volume`, `volume not found`.

**Planning, the config and the home.**
- `volume plan` and `collection plan` estimate from the configured drive's generation or
  `--generation` and never open the device; `volume init` still decides capacity (ADR-0010).
  `volume plan` plans the largest copy floor among the staged units it plans, and says whose.
- `config check` starts with the home and notes, at exit 0, a missing drive, a drive without
  `post_warning_bytes` and what that costs, and a collection whose root or tenant does not exist.
  An error for a missing drive names the real config file and `drive add`; `init`'s template
  carries a commented `post_warning_bytes`, and `init` ends with the next steps.
- Size input takes KiB to TiB (binary) in every size key; a bare or SI suffix keeps its field's
  meaning, so `post_warning_bytes = "99008M"` is still 99,008,000,000 bytes (OQ18).
- The "not initialized" error names the path and the rule that chose it, and offers `init` only
  for a new archive. **Run as root on a host with `/etc/tapectl/home`, tapectl refuses** and names
  `tapectl-op`, unless `--home` or `TAPECTL_HOME` names the home (`host check`, `--help`,
  `--version` and `completions` are exempt).

**Sources** (items 206, 207, 220).
- **Pending** means what the glossary says: a unit never archived or dirty. `collection status`
  says `3 pending (2 never archived, 1 dirty) · 3 staged, awaiting a write · 3 under-copied`;
  `collection plan` lists the staged units and the command that writes them.
- One collection with a missing root, an unknown tenant or archive set is that collection's
  error; the others are still synced, shown or planned.
- `collection sync --dry-run` makes every check the real run makes, so the two agree.
- A unit's row is committed only once its dotfile is written, and a unit 1.8.1 left
  half-registered is completed by the next sync, never called "nested".

**`unit check-integrity`** (items 208, 220). Each file is compared with the newest staged
version's record, as built:
- a file whose size differs from the record is **SIZE_MISMATCH**, exit 1, whether or not its
  modified time moved;
- a file at its recorded size whose content differs is **CHANGED** when its modified time moved
  since the snapshot (an edit), and **BITROT** when it did not; with no modified time recorded it
  is counted with BITROT and reported as `CHANGED or BITROT (no mtime recorded)`;
- BITROT, MISSING and SIZE_MISMATCH exit 1 (1.8.1 exited 0 whatever it found);
- **pending the CTO (Q40):** when CHANGED is the only finding the check exits **0**, with a note:
  ``1 file changed since the snapshot (v1): `tapectl snapshot create U` archives it``;
- **pending the CTO (Q42):** a size change is SIZE_MISMATCH even when the modified time moved;
  whether it becomes CHANGED then is not decided.

**Smaller fixes** (item 220): `audit --action-plan` gives a staged unit the write as its fix and
names each never-written unit once; `completions zsh | head` exits 0 (it panicked with 101);
`volume identify --json` prints one object; `report fire-risk` says it judges copies; after an
interrupted copy the hints agree, and `volume info` no longer shows `Status: initialized` beside
a `Sealed:` time; raw tracing lines no longer reach the operator (the heir's "matched no
configured [[backends.lto]] entry" is a debug line on the read paths); `restore unit --dry-run`
without `--from` finds the one tape that holds the unit.

## Help and output

- The top-level help is grouped by job in workflow order (Set up, Sources, Stage and write,
  Check, Restore, Drive and cartridges, Catalog and maintenance). The global options sit under
  their own heading. `-h` gives one line per command and flag, `--help` the full text, and help
  wraps to the terminal; the most-used commands have EXAMPLES. `--verbose` says it is debug
  tracing. Each command's `--help` states its exit codes, and `docs/cli/README.md` has the one
  table.
- Tables are aligned columns without boxes, in one header case, fitted to the terminal; times
  are UTC in text and RFC 3339 with `Z` in JSON; sizes are human everywhere; plurals are real.
  The CLI says "drive" where it said backend (`Drive:` in `volume info`). Colour marks verdict
  words only (`ok`, `passed`, `clean`; `warning`; `FAIL`, `refused`, `error`), only on a terminal,
  and never under `NO_COLOR`.
- `install-systemd.sh` installs bash completion for `tapectl` and `tapectl-op` and the man pages
  (OQ17).

## Exit codes that changed

| Command | 1.9.0 |
|---|---|
| any removed spelling | 2, refused by name |
| `collection sync`, `collection status`, `collection plan` | 1 for warnings (a folder refused for its name, an entry outside every unit, a unit marked missing), 2 for errors (a root missing or not absolute, an unknown tenant or archive set, permission denied, a dotfile not written); the worst across collections |
| `status` | 0 when it read the catalog (or, for an account that cannot, showed what it can), 2 when it could not |
| `unit check-integrity` | 1 on BITROT, MISSING or SIZE_MISMATCH; 0 when CHANGED is the only finding (Q40, pending) |
| `report copies`, `tape-only`, `dirty`, `age` and `snapshot list` with an unknown `--unit`; `report verify-status` and `health` with an unknown `--volume` | 2 (`unit not found: nope`, `volume not found: …`); `report copies --unit nope` printed nothing and exited 0 |
| `completions zsh \| head` | 0; it panicked with 101 |

An unknown `--unit` or `--tenant` is an error everywhere. `audit` keeps 70 for its own errors,
and `volume verify` 3 for every error.

## JSON changes

- **Errors are JSON on stdout under `--json`**, clap's own usage errors and the renamed
  spellings' refusals included, and the `error:` line still goes to stderr:

  ```json
  {
    "error": "unit not found: nope",
    "exit_code": 2
  }
  ```

- Every document is pretty-printed; each command has one shape: `snapshot create` and
  `stage create` print an array of one object per unit, whether one unit was named or several;
  `volume identify --json` prints one object.
- **Names replace display ids:** `unit list`, `unit init` and `unit info` carry `tenant` and
  `archive_set` instead of `tenant_id` and `archive_set_id`; `key list` rows carry `tenant`. Ids a
  later command takes as an argument (a stage set's, a contact's, an event's) stay.
- **The copy floor is `copy_floor`** wherever a key carried it as `min_copies`: `report
  fire-risk`, `report needs` (`copy_floor`, `copy_floor_short`), `stage clean`'s `retained[]`,
  and `under_copied[]` in `volume write`, `volume resume` and `collection run`. `stage list`
  rows carry `copies`, `copy_floor` and `owing`.
- `cartridge list` and `cartridge info` say `generation` (it was `media_type`).
- `collection status`'s `pending` takes the glossary's meaning, beside new `never_archived` and
  `staged`; `report dirty` and `unit info --dirty` say `never_archived` for a unit never
  archived; `report reclaimable`'s count is `reclaimable`.
- **Added:** `summary`, `next_command` and `units_released` on `volume write` and
  `collection run`; `kept_from_write` and the move keys on `volume resume`; `last_full_read` on
  `volume verify`; `copies_from` and `copy_floor_unit` on `volume plan`; `notes` on
  `config check`; `already_there` on a move; `changed` on `unit check-integrity`; and on
  `status`, `home`, `home_source`, `home_pointer`, `units`, `due_verify`, `interrupted` and
  `next` beside the keys it had.

## Scripts

- **`scripts/first-run.sh`.**
  - Step 7 walks the staging path as the service user (item 199, #511): a directory above it
    the service user cannot traverse is named with the `setfacl -m u:tapectl:x` line that fixes
    it; a missing parent is refused ("Is its filesystem mounted?"); a missing staging directory
    is created 0700 for the service user; no `chown` is offered.
  - Step 8 runs `drive add` and sets the drive's `post_warning_bytes` from the profile's
    `POST_WARNING_BYTES` (item 200), never over a different value.
  - Step 11 configures a profile's `COLLECTIONS` with `collection add`, and reads
    `collection sync`'s exit 1 as warnings.
  - Step 12 reads the chip before it asks for the test cartridge's serial: it reads again once on
    a unit attention, and refuses an empty drive before anything is asked (#511).
  - Step 13 is one copy loop: `volume write --full-confirm --move-to` the first place, with no
    separate verify and no `stage clean`; its exit status is read from the write's table. The
    resume passes the same flags. A sealed re-entry reads the tape back only when no full
    readback is recorded (OQ15). This catalog's own volume still loaded is never erased. An
    attempt abandoned before its seal is written again under the same label (#401).
  - Step 14 names the next command: the first tape on an empty catalog, else the next copy.
  - `--upgrade`'s step 2 backs up with the OLD binary's own spelling (`db backup --to` before
    1.9.0, `db backup PATH` from it).
- **`scripts/lifecycle-suite.sh`** keeps `sg_read_attr`'s own message and reads again on a unit
  attention (#511), and reads `unit check-integrity`'s CHANGED and exit codes.
- **`contrib/hosts/home2.profile`**: staging's comment describes the unencrypted RAID0
  (item 198), `POST_WARNING_BYTES=99008M` (item 200), and no `COLLECTIONS` (item 204).
- **`scripts/install-systemd.sh`** installs the completion and the man pages; every script on
  the new binary uses 1.9.0's spellings.

## On-tape changes

None (item 221). No golden pin moved: RESTORE.sh, MANIFEST.toml, the short seal, File 0, File 1,
the front index, the seal and the envelopes are 1.8.1's, and `requires` is computed as in 1.8.1.
On-tape text keeps its words where the CLI's changed ("ID thunk" in RESTORE.sh's comments, File
1's three commands). A 1.8.1 reader reads every tape 1.9.0 writes, and the other way round. The
writer field names 1.9.0.

## Catalog migrations

session's directory, not a column.

## Upgrading from 1.8.1

`scripts/first-run.sh --upgrade` takes the steps every upgrade takes: the catalog backup with the
old binary, the install, the rehearsal and the Heir Kit (`docs/install.md` §10). What 1.9.0 asks
besides:

- **Old spellings are refused.** A script, cron line or alias of yours that uses one of those
  in these notes' "Renamed commands and flags" stops with exit 2 and the new spelling (under `--json`, as a JSON error on stdout). Fix
  each as it is named; the three File 1 commands need nothing.
- Nothing in `config.toml` needs editing: `[[backends.lto]]` keeps its name, and existing
  `[[collections]]` tables load as they are. On a host whose profile sets `POST_WARNING_BYTES`,
  look with `tapectl-op config get post_warning_bytes`: step 8 applies it, and an upgrade does
  not run step 8.
- Step 6 re-renders `tapectl-op` and installs the bash completion and man pages; a new login
  shell completes `tapectl` and `tapectl-op`.
- A profile's `COLLECTIONS` is read only by step 11, which an upgrade does not run; add a
  collection to an installed host with `tapectl-op collection add NAME ROOT --tenant TENANT`.
- With no migration, the rollback is the binary alone: `sudo cp -p /usr/local/bin/tapectl-1.8.1
  /usr/local/bin/tapectl`.
- Have a test cartridge the catalog has never seen for the rehearsal.
