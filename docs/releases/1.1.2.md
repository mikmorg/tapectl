# tapectl 1.1.2: release notes

What changed between `v1.1.1` and 1.1.2, for the person who runs tapectl. The record is
`git log v1.1.1..v1.1.2`, the issues under the label `1.1.2`, the two reviews of 2026-10-15
(`docs/audits/2026-10-15-design-review.md` and `docs/audits/2026-10-15-1.1-diff-review.md`),
and ADR-0012's amendment "2026-10-15 (later)" (items 65–70).

- **A patch release.** No generated on-tape byte changed: `tests/on_tape_golden.rs`,
  RESTORE.sh, File 1 and the on-tape `catalog.db` are untouched. Volumes written by 1.1.1
  and 1.1.2 are the same format.
- **No catalog migration.** The catalog stays at schema 036; 1.1.2 opens a 1.1.1 catalog
  as it is, and a 1.1.1 binary still opens a catalog 1.1.2 has used. Upgrading home2 is
  replacing the binary (handoff (f)) and one `config set` (below).
- **Most of it is from the two reviews:** one high (a rebuilt tape with no seal counted as a
  copy), a dozen mediums in the consent, coverage, recovery and forensic paths, and the
  harness checks that could not fail.

## Before upgrading home2

- **Set the full-readback clock once:** `tapectl-op config set
  defaults.verify_interval_days 365`. home2 has no archive sets, so until this is set
  `audit` never says a tape is overdue for a full readback (#453, #454).
- **The next write depends on a drive fact the HP LTO-6 has not yet shown 1.1.2.** A fresh
  `volume write` now treats a seal position that cannot be read as "unreadable", not "no
  seal", unless the drive reports END OF DATA there (#460). mhvtl does; the real drive is
  expected to and proves it at the step-12 rehearsal that handoff (f) step 7 requires
  before the next write. If it did not, writes would refuse (fail closed), never overwrite.

## Changes an operator will notice

### Writing, initialising, resuming

- **An unreadable seal is not an absent one** (#460). `volume write` and `volume init
  --force` refuse a tape whose seal marker could not be read unless the drive shows the
  tape ends before it; `--force` does not override this. A resume that finds its own tape
  sealed records `sealed_at`.
- **`volume write --init` checks what the catalog alone can before it touches the
  cartridge** (#445): nothing staged, a staged slice missing, a tenant without a key, no
  escrow. A refusal only the tape can raise after the init (the capacity gate, the
  quiet-host question) still exits 2, and stderr and `--json` (`initialized: true`) say the
  volume stays initialized.
- **The retire family waits for no live session** (#461): `volume retire`, `cartridge
  retire`, `cartridge mark-erased`, `volume compact-finish` and `volume move` exit 75,
  changing nothing, while a `volume init`, `write`, `resume` or `verify` holds the volume.
  A confirm no longer seals a volume retired during its readback; `volume init` takes its
  lock before it records anything; the planned-to-running flip is one transaction.
- **Proven-blank init, hardened** (#444): the verified-erase proof is void when the chip's
  lifetime-written figure grew since the erase's verify (another tool wrote the tape). The
  mhvtl gate now runs `cartridge erase` followed by `volume init` with no `--force`.

### Consent and coverage

- **`unit mark-tape-only` refuses a never-archived unit whatever its directory** (#462):
  the Tier-3 refusal used to be skipped when the source was missing or unmounted.
- **The retire family judges required locations by name and asks `min_locations`** for a
  tape-only unit (#463), as `audit` does; the Tier-1 evidence line counts only the unit's
  current versions, and "rests on N copies" is the least-covered version's count.
- **`min_copies` below 1 and `min_locations` below 0 are refused by name** at load, `config
  check`, `config set` and `archive-set create|edit|sync` (#453). A catalog row already
  holding 0 keeps working.

### Staging

- **The catalogue and the tape say the same thing** (#464). `stage create` refuses a file
  the snapshot lists but the unit's exclude patterns now exclude, and after dar it compares
  the isolated catalogue's file list with the files it hashed and refuses any difference (a
  wildcard inside a directory pattern prunes more in dar; a file appearing in a living
  source mid-stage). The listing costs about 9 s per 100,000 files.
- **Staging a living source** is documented (#455): stage from a read-only snapshot shown
  at the unit's own path in a private mount namespace, or hold the source still.
- **dar runs with `-N` and `LC_ALL=C` everywhere** (#465); an ENOSPC mid-slice names the
  slice; a non-UTF-8 file name is refused at `snapshot create`, by name; stage-set ids are
  never reused (`meta` key `stage_set_id_high_water`) and stage reports never overwritten;
  `staging clean` removes what a killed run left (a never-staged set's catalogue directory,
  `<home>/tmp` entries a day old, `clone-*`/`compact-*` directories quiet for an hour).
- **A seccomp filter that did not take in the dar child is a warning** (#447).

### Collections

- **`collection run` refuses at plan time a label `volume write` would refuse** (#475): an
  unresolved write session (resume it) or a recorded seal, before a batch is staged. One
  predicate serves both commands. Staged data that already fills the tape says to write it
  first, instead of "can never be batched".
- **`collection plan` shows the largest pending unit as a share of the tape** (#456), with a
  note when it passes a tenth of a cartridge (ADR-0012 item 69). The selector is next-fit
  in name order, as it always was; the documents said first-fit.

### Recovery

- **A rebuilt tape with no valid seal marker is not a copy** (#458, the review's high).
  `catalog rebuild --from-volume` records it as an aborted write (`initialized`, writes
  `aborted`, positions `pending`) and says so; a seal naming an unknown required feature
  refuses the rebuild. Only a tape whose seal reads, names it and binds its front index is
  recorded sealed.
- **A rebuilt home carries its dar catalogues** (#473): the rebuild puts each stage set's
  catalogue back from the operator envelope, so restores stream and a copy written from the
  rebuilt home carries them; `volume write` warns of a set with none.
- **The rebuild goes on past a tenant envelope unreadable in both copies** (#451) when the
  operator envelope's `catalog.db` names each unit's owner; the tenant-key recipe restores
  into a new directory; the operator envelope is found by kind, not by a tenant's name; the
  decrypted `catalog.db` stays under the home, 0700 (#459).
- **`volume read-slices --version N`** (#474); without it reclaimable and purged versions
  are skipped; staging space is checked first; a read that does not finish removes what it
  wrote. `compact-read` stages only sets it read in full.
- **`db backup --to X` leaves X at 0600** (#459).

### Audit, health and the Heir Kit

- **`volume_verify_age`** (#454): a per-volume full-readback clock that names the volume,
  its cartridge and its place, so a fresh home copy no longer hides an unread offsite one.
  The per-unit `verify_age` counts only copies that still count.
- **`[defaults] verify_interval_days`** (#453): the clock for units with no archive-set
  interval, used by `verify_age`, `volume_verify_age` and the age limit on continuing an
  interrupted full readback.
- **Heir Kit cover sheet** (#448): the restore example lists first and restores `--all`;
  it names the drive generations that read the sealed volumes (LTO-6: an LTO-6 or LTO-7
  drive) and the SAS/HBA interface; one-unit disk space; RESTORE.sh's own tool list; a
  "Tapes are at" box. `escrow_kit_stale` also fires after a tape moves.
- **Forensics** (#466, #467): a command's journal writes wait out a busy catalog, and a
  page 0x2E that still cannot be written is printed whole; `drive eject` takes its sweep;
  `drive cleaned` journals its chip read; worn-cartridge warnings use any 0x2E reading
  since the last full readback; the read-error trend records what the verify read and
  skips points of unknown scope; `host check` reports unknown contender units and compares
  process names on 15 characters.
- **Remedy strings** (#468): every command a refusal or warning names is one the code
  accepts in that state.

### Installing and operating

- **`first-run.sh` step 13** (#446, #469): routes `volume init`'s refusals by stable
  phrases (pinned by a test), takes the erase consent word from `--json`, takes
  `--erase-label` from the flag only (never a profile), and names `sudo -u tapectl -H
  tapectl` (or `tapectl-op`) in its remedies. The re-entry harness now drives the erase
  branch the production fresh start takes.
- **Timers** (#470): the backup never prunes the copy it just wrote (a clock that went
  backwards); exit 75 is success for the backup and audit units.
- **`config set`** names the fix wherever the docs said "there is no backend edit".
- **`docs/cli`** lists every command's own `--version` option (#472).

## Testing

- The mhvtl gate's Rust legs pass only when every test they run said `ok`, and a gate run
  turns an on-media skip into a failure (#471); the leak scan also needles every tenant key
  (#450); the erase-then-init leg (#444).
- An ungated test scans a sealed volume's plaintext zones (File 0 to 3 and the seal) for the
  fixture's tenant, unit and file names, plaintext hashes and key recipients, with a
  planted-leak control (#450).
- The lifecycle suite's checks that could not fail have positive controls (#471); the
  plaintext scan proves its slices landed on the scanned device.
- `tests/heir_restore_sh.rs` fakes `age`; the gate is the heir path's only test with the
  real tools, and each run record names the age version (#457; this VM's age CLI is 1.1.1).
