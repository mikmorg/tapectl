# tapectl 1.5.0: release notes

What changed between `v1.4.0` and 1.5.0, for the person who runs tapectl. The record is
`git log v1.4.0..` on the 1.5.0 tree, issue #485 and ADR-0012 item 109.

- **File 1, a re-pin release.** File 1 and RECOVERY.md answer the fifth fresh read's remaining
  findings (#485), then a sixth read under item 108's stopping rule. RESTORE.sh, MANIFEST.toml,
  File 0, the front index, the seal, the envelopes, the index and the on-tape `catalog.db` are
  written as 1.4.0 writes them; no golden pin moved.
- **The Heir Kit carries the program that made it.** `key escrow-kit` writes a fourth file,
  `tapectl-<version>`, a copy of the running tapectl binary (mode 0755), and the cover sheet and
  the HTML page name it with its size and sha256. An heir's one tool for reading around a damaged
  slice no longer depends on the repository surviving.
- **No catalog migration.**
- **Issues this release finishes:** #485.

## On-tape changes

**File 1** gained:
- Start here, step 8: "done" holds over the tapes you hold. No tape names one written after it,
  and a tape from before 1.3.0 has no index to check against.
- "Files deleted before the newest version" (in "The rest of the box"): `--list --version` for
  two versions, `grep` and `awk` to print the paths only the older one has, and `--restore
  --version --path` to bring one back.
- Where to get a newer dar: a newer distribution release (`apt-cache policy dar`), dar's own
  site and its SourceForge project, and building a source tarball.
- "Compressed units": a short way to a unit's `dar_command` with an escrow or operator key (one
  envelope read by hand, `tar -xOf - MANIFEST.toml`), and "three times" as a rule of thumb, not a
  ceiling.
- "The tape drive": a cartridge's generation read without a drive (the label, the cover sheet's
  own line), and one working setup (adapters and connectors for an external and an internal drive).
- After a failed `dd`, the head is inside the file: rewind and `fsf` to the wanted position
  (manual steps, rung 3, and RECOVERY.md).
- Glossary entries "Index" (the front index versus the envelope's `index/`) and "Catalogue" (the
  Heir Kit's, an installation's, a dar catalogue, `catalogs/`); the placeholders `OPERATOR_NAME`
  and `FIRST_TAPE_POSITION`; `POSITION` defined where a slice is copied by hand.
- "tapectl itself" looks in the Heir Kit first, for `tapectl-X.Y.Z`, checked against the cover
  sheet's sha256.

The sixth fresh read (an heir holding only the escrow key; verdict "mostly", two serious findings,
both fixed by the CTO's ruling, no seventh read under item 108) added:
- "Done" checks the Heir Kit's catalogue: every unit it lists on a sealed tape is restored or
  named as held only on tapes you do not have, since a kit made after the newest tape in the box
  is the one thing that can name a tape written after it. Its per-unit query prints each unit's
  uuid.
- A done state for a unit whose every copy is damaged: restored as far as its copies allow, its
  `.tapectl-damaged-files.txt` kept, the loss written down.
- Smaller fixes: a one-unit tape's directory in the `--all` check; one answer for where to restore
  the units after a failed slice; RESTORE.sh's `--swap-tapes` and `done` before the hand route;
  the summary lines that are above 0 by design; the check for a unit with no dar catalogue;
  `tapectl_version` in File 0's `grep`; `age` before `age-keygen`; each tape's script saved as
  `RESTORE-<label>.sh`; the Bech32 letters a secret never holds; the kit's program copied to a
  Linux disk before it runs; `--home` under `sudo`; `init --operator` as root; the whole
  MANIFEST.toml by the short way; and how long a whole tape takes to read.

**RECOVERY.md** repeats the parts that concern one envelope: the failed `dd`, a dar catalogue named
as such, and an `awk` over `index/paths.tsv` for files only an older version has.

**Fixed points.** RESTORE.sh's "this tape needs tapectl" text stays "tapectl 1.1.0" and `requires`
stays empty, so 1.x tapes read each other's.

## tapectl changes

- **`key escrow-kit`** copies `std::env::current_exe()` into the kit as `tapectl-<version>`,
  reads the sha256 back from the copy, and prints it with the size on COVER.txt and
  escrow-kit.html (with the machine type and the release tag of the source). Step 4 of the
  sheet's WHAT TO DO FIRST says to run it as `./tapectl-<version>`. `--json` adds
  `tapectl_copy`, `tapectl_sha256` and `tapectl_bytes`. A program that cannot be copied refuses
  the kit by name and leaves no partial copy. The kit copies whichever binary runs the command,
  so make it with the installed production build. Regenerating a kit after an upgrade leaves the
  older `tapectl-<oldversion>` beside the new one: delete it.

## Upgrading

home2 runs 1.1.0 and upgrades in place, straight to 1.5.0 (`docs/handoff.md`, (f)). 1.5.0
contains 1.1.1, 1.1.2, 1.2.0, 1.3.0 and 1.4.0; read their notes, not restated here. Migrations 036
(1.1.1) and 037 (1.4.0) apply on the first open.

1. **Back up the catalog first, with the old binary:** `tapectl-op db backup --to <path>`.
2. **Tapes written before the upgrade are not touched.** New writes carry 1.5.0's File 1.
3. **Regenerate the Heir Kit** with the installed binary and reprint COVER.txt: the sheet now
   names the kit's copy of tapectl and its sha256.
4. **The on-tape authorizations of 1.2.0 to 1.5.0 end when v1.5.0 is installed** (ADR-0012 items
   72, 81, 104, 105 and 109). After that a failing `tests/on_tape_golden.rs` is a CTO decision.
5. **The step-12 rehearsal** proves the new binary on the HP drive before the next write.
