# tapectl 2.0.0: release notes

What changed between `v1.9.2` and 2.0.0, for the person who runs tapectl. 2.0.0 writes
**Layout Version 3**, a new layout on tape, and reads and writes nothing else. By the version
rule (ADR-0012 item 201) the minor moves when the bytes tapectl writes to tape change or a
command or flag spelling is removed; this release does both on a large scale and drops
compatibility with 1.x on purpose (item 242), so it is a major.

## Read this first

- **2.0.0 neither reads nor writes Layout 2** (item 242). A tape written by 1.1.0 to 1.9.2 is
  read with tapectl 1.9.2 or with the `RESTORE.sh` on that tape's own File 2. tapectl 2.0.0
  knows such a tape when it meets one: it reads its label from File 0 and nothing else, says
  "this is a tapectl volume of Layout 2, label L; read it with the tapectl that wrote it or
  with the RESTORE.sh in its own File 2", and never writes over it. `volume init` over it is
  refused; `cartridge erase` with the typed label is the way (item 269).
- **There is no upgrade from 1.x** (item 258). A 1.x catalog is refused by name ("made by
  tapectl 1.x; tapectl 2.0.0 does not upgrade it"); the catalog is one baseline schema, with
  no migration from the 41 of 1.x. `scripts/first-run.sh --upgrade` refuses an installed
  tapectl below 2.0.0, and its first real use is the release after this one.
- **Production starts fresh** (item 244): a new catalog, new operator and tenant keys and new
  unit identities (the units' `.tapectl-unit.toml` dotfiles deleted first). The escrow
  identity may be kept, if its paper still passes `age-keygen -y`. The Layout 2 cartridges are
  erased and written again (items 245, 269); nothing of them is read. `docs/install.md` §10
  and `docs/handoff.md` give the order.
- **GNU tar 1.35 built with ACL support is required on every host that writes** (items 273 to
  275; #563). tapectl refuses to stage with a tar below that floor, and `config check`,
  `init`, `setup` and `stage create` say which tar they found. A host whose own tar is older
  builds the upstream release into `/usr/local` and names it in `[tar] binary`
  (`docs/install.md`, "The writer's tar"). Reading a tape needs no such tar: any tar restores
  one.
- **dar is gone** (item 241): from the data zone, from the host's dependencies, from
  `config.toml` (the `[dar]` table is now `[tar]`, and a `[dar]` table is refused as an
  unknown key) and from `first-run.sh` (`--dar` and `DAR_BIN` are now `--tar` and `TAR_BIN`).
  tapectl compresses in-process, so the host needs no `gzip`, `xz` or `zstd` to write; the
  heir needs the tool of an algorithm only for a unit that uses it.

## The format: Layout Version 3

What the operator sees of it (the byte format is `docs/design/volume-format-v3.md`):

- **A unit is a pax tar stream** that GNU tar writes from the exact file list tapectl gives
  it, with `--numeric-owner`, extended attributes and POSIX ACLs. tapectl reads the stream as
  it passes: it checks the members against the snapshot, takes each file's sha256 from the
  bytes that go to tape, and notes where each member starts. The unit's root folder is a
  member of the stream (item 306), so a restore into an empty destination gives it its
  recorded owner, times, attributes and ACL (item 303). Sockets are left out of every unit,
  and the snapshot says so (item 270). A hard link is kept as a link (item 256); two
  hard-linked names of one symbolic link are two `l` rows (item 299). A file whose name is not
  valid UTF-8 is archived and restored by its bytes (item 297, #569).
- **The stream is cut at member starts** into slices of at most `slice_size` bytes (a
  multiple of 512): a slice holds whole files, and a file larger than a slice gets a run of
  slices to itself (item 283). Each slice is its own tape file, age-encrypted in memory; no
  plaintext reaches staging.
- **Compression is optional, per archive** (items 280, 284 to 287). `compression` takes
  `none`, `gzip`, `xz` or `zstd`; each slice is compressed alone, after the cut and before it
  is encrypted; `compression_level` sets the level (gzip 1 to 9, xz 0 to 9, zstd 1 to 19; the
  algorithm's own default when unset). The 1.x values `bzip2`, `lzo`, `lzma` and `lz4` are
  gone.
- **A file table and an id map replace dar's catalogue** (items 254, 265, 272, 276 to 278).
  Every tenant envelope carries, for each unit copy on the tape, each path with its size, the
  sha256 of the bytes on this tape and where it starts; the catalog database keeps the same
  table. The id map records who each numeric user and group id was; a restore shows it and
  never acts on it. A listing, a one-file restore and the per-file check read the file table.
- **Every tape may end early, and `requires` is empty.** The short seal is part of the layout,
  so a tape no longer declares `short-seal` or `spanning` (item 258(a)).
- The operator envelope's `catalog.db` has one generation, not three. File 1 (the system
  guide), `RECOVERY.md`, `RESTORE.sh`, the front index, the envelopes' contents and the
  cross-volume index all changed with the layout (item 243).

## Spanning: every unit continues on the next cartridge

- **There is no opt-in and no `cut` unit** (items 246, 288). A tape is written in the queue's
  order; when the drive reports its early warning the slice in flight finishes, the seal says
  where the tape ended, and the slices not written stay staged and are written first on the
  next cartridge. A unit that goes on to a second cartridge rests on two; its version is not
  current, and its tail stays staged, until the next cartridge is written.
- **The queue is filled to the warning** (item 289). The next unit is started even when it
  does not fit, and the plan lists it past the cartridge's nominal capacity, on a drive that
  declares `post_warning_bytes`. Without that key the plan stops at the fill ceiling and the
  rest continues.
- `volume rewrite` and compaction carry a volume that holds a range (item 260; the 1.x refusal
  is gone). A run written to a cartridge must be of the generation of every range of the same
  version it adjoins, in both directions (item 300).

## The restores

- **One reader** restores every path (item 264). It feeds tar whole members, by byte range
  from the file table, and checks each member against the file table as it is handed over and
  each restored file again on disk (`--no-file-check` skips the second read). A restore of a
  unit writes no slice to disk. It holds one whole slice in memory and warns, before it reads
  and in `config check`, when that figure exceeds the host's available memory (item 298).
- **A restore may start on any tape of a span** (item 266): it takes the files that tape holds
  whole and lists the rest with the cartridges that hold them.
- **The repair is from another copy.** A bad slice is left out, the damaged files are listed,
  and the repair is to restore those paths from another copy of the version. It builds in a
  hidden directory on the destination's own filesystem, so installing a file is a rename that
  keeps its owner, times, attributes and ACL (item 304).
- `catalog rebuild` refuses a unit whose name matches a catalog unit under another uuid and
  rebuilds the rest of the tape (item 249); a row a rebuild recorded from an unreadable seal
  may be promoted by a later clean read (item 302).

## RESTORE.sh, File 1 and the Heir Kit

`RESTORE.sh` is one file, the same bytes on every tape. It restores whole units, named paths
(`--path`, `--paths-from`) and the repair with the stock tools (`age`, `tar`, `mt`, `dd`,
`sha256sum`, and the decompressor of a compressed unit); `--where` and `--find` read the
cross-volume index. It keeps one prompt, for the next cartridge of a unit that continues
there; "I do not have it" is an answer (items 255, 266, 267). Its work directory is inside the
destination by default, and `--work` replaces `--scratch` (item 271). A restore run with
`--no-file-check` whose tar failed ends "RESTORE INCOMPLETE" (item 301). File 1 and each
envelope's `RECOVERY.md` give the manual path and every command in them is run by a test. The
Heir Kit carries this release's static binary; print its new `COVER.txt` and replace the
sheets of an older kit, which cannot read these tapes.

## Removed commands, flags and keys

Compared by `docs/cli/` and the man pages at `v1.9.2` and now. No command is removed; one is
added.

| 1.9.2 | 2.0.0 |
|---|---|
| `archive-set create/edit --allow-spanning`, `allow_spanning` in `[defaults]`, an archive set or a dotfile, `writes.may_span` | gone: every unit continues at the early warning (item 288) |
| `archive-set create/edit --preserve-fsa`, `preserve_fsa` | gone: tar keeps no `chattr` flags (item 253) |
| `[dar]` `binary` in `config.toml` | `[tar]` `binary` (a bare name on `PATH`, or a path) |
| `compression` values `bzip2`, `lzo`, `lzma`, `lz4` | refused; `none`, `gzip`, `xz`, `zstd` only |
| `restore unit --spool`, `restore units --spool` | gone: a restore writes no slice to disk |
| `restore unit/units --scratch` (where slices wait for dar) | not used by a restore of units; `restore file --scratch` is where the file is extracted before it is placed |
| `RESTORE.sh --scratch` | `--work` |
| `RESTORE.sh --slices-from`, `--swap-tapes`, `--stream-tapes`, `--fill-from`, salvage mode, `--ignore-zeros` | gone (items 255, 264, 267); the repair is `--paths-from` with the damaged-file list |
| `first-run.sh --dar`, profile `DAR_BIN` | `--tar`, `TAR_BIN` |
| the 1.9.0 renames (`backend add`, `staging clean`, `catalog ls`, `report summary` and the rest of that release's table) | no longer refused by name: they are an ordinary unrecognized subcommand or flag (item 258(d)); use the 1.9.0 spellings |
| the refusals of removed config keys (`[packing]`, `[labels]`, `defaults.hash`, `hardware_compression`, `block_size`) | refused as unknown keys by the config parser |

Added: `tapectl drill record` (below), `--compression-level`, `restore … --no-file-check`,
`[defaults] drill_interval_days`, and a description of `db import` that says what it does: it
puts a backup in the live catalog's place and keeps the one it replaces.

Changed in what it says or does: `restore unit/units` and `restore file` check free space
against the unit's (or file's) size in `--to`, not twice that; `stage info` reports the unit's tar, not its dar; `preserve_acls` is no longer subsumed by `preserve_xattrs`
and is tar's `--acls`; with it off no ACL is stored (item 296).

## Other behaviour that changed

- **The heir drill has a record and a clock** (item 247). Run `RESTORE.sh` from a volume as an
  heir would, then `tapectl drill record LABEL`; `audit` warns (`drill_age`) when the newest
  record is older than `[defaults] drill_interval_days` (365 when unset). The record names the
  sha256 of the `RESTORE.sh` the volume carries.
- **`audit`** also warns of a folder under a collection root that is not a unit (#534), counts a
  unit whose newest snapshot was never staged as pending (#529), and holds two places for the
  units through `[defaults] copies_at` (item 257).
- **`init` writes an empty exclusion list** and every snapshot reports what a pattern left out
  (item 252, #542). **No notification is built in** (item 250).
- `db fsck --repair` refuses, deleting nothing, when the integrity check fails;
  `snapshot create --all-pending` exits non-zero when it skipped a unit (item 249).

## On-tape changes

All of them: Layout Version 3 (item 243). The data zone (a pax stream cut at member starts,
each slice compressed alone when asked and age-encrypted), File 0's magic `tapectl-volume-v3`
and empty `requires`, File 1, `RESTORE.sh`, `RECOVERY.md`, the envelopes' contents (the file
table and id map, the `MANIFEST.toml`), the cross-volume index and the on-tape `catalog.db`.
The byte pins in `tests/on_tape_golden.rs` and the recorded tape in
`tests/fixtures/recorded-2.0.0/` hold them; a pin that fails means the format changed, which
is a decision and not a re-pin. The authorization to change on-tape bytes ends when the
acceptance run's drill passes (item 268).

## Catalog migrations

None from 1.x: the catalog is one baseline schema (`user_version` carries tapectl's own
application id), and a 1.x catalog is refused by name. Start a new one with `init` or `tapectl
setup`.

## Upgrading

There is no upgrade from 1.x. The way is a fresh start (`docs/install.md` §10, `docs/handoff.md`):
build the host's tar if its own is below the floor, install 2.0.0 with `scripts/first-run.sh`,
delete the units' dotfiles first so that `collection sync` mints new identities, and erase the
Layout 2 cartridges with `cartridge erase` and the typed label before they are written again.
Keep tapectl 1.9.2 until every Layout 2 tape you still need has been read.

## The acceptance run

`v2.0.0` is tagged when the build is complete and proven on test cartridges. The operator then
does the fresh start on the production host, writes both cartridges at real scale, and runs
the drill with the Heir Kit's keys and File 1's steps (items 263, 268). If it passes, the
cartridges are production and the on-tape authorization ends; if it fails, they are test
articles, the fix is a new release (the minor moves if on-tape bytes move), and the run is
repeated by another fresh start with new keys and a new kit.
