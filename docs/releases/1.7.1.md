# tapectl 1.7.1: release notes

What changed between `v1.7.0` and 1.7.1, for the person who runs tapectl. The record is
`git log v1.7.0..` on the 1.7.1 tree, issues #491, #492 and #493, and ADR-0012 items 147-160.
No byte that tapectl writes to tape changed, so by the version rule this is a patch.

- **A unit can ask for copies at named locations** (#493). Its *copy targets* are a map from
  location to count, `copies_at`, set in the unit's dotfile, on an archive set or in
  `[defaults]` (items 148, 149, 155 and 156). A copy *at* a location is an eligible tape
  shelved there, or a warehouse deposit there (item 150).
- **The copy floor is now the larger of `min_copies` and the map's sum**, times the tape-only
  multiplier for a tape-only unit (item 149). A unit with no map keeps `min_copies`. An archive
  set's `required_locations` counts as one copy at each name, so **an archive set whose
  `required_locations` names more places than its `min_copies` has a higher floor than in
  1.7.0** (below). home2 has no archive sets.
- **`report needs`** gives each unit's target, copies and shortfall per location, and `audit`'s
  `location_presence` judges the map (item 160).
- **Auto-stage for a location** (items 151-154, 157-159): `stage for-location X --volume LABEL`
  works out what X needs, packs it into that volume and stages it; `volume write LABEL
  --for-location X` writes only that and moves the tape to X.
- **Item 94's start** (#492, item 147): a spannable set larger than one tape now starts right
  after the owed runs, and the whole units it displaces follow its tail on its last tape.
- **#491:** test fixtures made robust to the ~170-byte spread of age's header, and a rare false
  refusal in the span planner's read-back fixed.
- **One catalog migration, 040.**
- **Issues this release finishes:** #491, #492 and #493, once the full gate and tape chain pass
  on the 1.7.1 commit (below).

## On-tape changes

None. No golden pin moved: RESTORE.sh, MANIFEST.toml, the short seal, File 0, File 1, the front
index, the seal and the envelopes are 1.7.0's, and `requires` is computed as in 1.7.0. A 1.7.0
reader reads every tape 1.7.1 writes, and the other way round.

The operator envelope's `catalog.db` keeps generation 3's shape: it carries neither new column.
Its `user_version` mirrors the catalog's schema level, so it reads 40 where 1.7.0 wrote 39. No
golden pin covers it, as for 38 and 39.

## Per-location copy targets (#493)

**Where the map is set** (item 155, and `docs/configuration.md`):
- the unit's dotfile, a `[policy.copies_at]` table with one `location = count` line each (TOML's
  inline `copies_at = { home = 1 }` under `[policy]` is the same table):
  ```toml
  [policy.copies_at]
  home-rack = 1
  offsite = 2
  ```
- an archive set: `archive-set create|edit --copies-at NAME=N`, repeated for each location,
  replaces the set's whole map; `copies_at` in an `[[archive_sets]]` table, applied by
  `archive-set sync` when the table names it; `archive-set info` shows it (`Copies at:`);
- `[defaults] copies_at`, inline or as a `[defaults.copies_at]` table. `init` does not write it.

**How it resolves** (item 156):
- The most specific layer that sets `copies_at` wins entirely: dotfile, then archive set, then
  `[defaults]`. Maps never merge, and an empty map is a setting ("no targets") that hides the
  layers below.
- An archive set's `required_locations` is shorthand for one copy at each name, folded into the
  set's map with the set's own `copies_at` laid over it name by name. Either key makes the set's
  layer set the map. `required_locations` itself is unchanged.
- Each count is 0 or more; 0 asks for none there. A negative count is refused by name: at load
  and by `config check` for `config.toml`, by `archive-set create|edit|sync`, and as an
  unresolvable policy for a dotfile.
- Each name a `copies_at` key brings must be a registered location, or the unit's policy is
  unresolvable, naming the name and the layer (item 155). `archive-set create|edit|sync` refuse
  an unregistered name, as they refuse a `required_locations` one. `config check` does not
  look: the names are checked against the catalog when a policy is resolved.
- `location rename` rewrites the name in every archive set's `copies_at`, in every unit's frozen
  map and in every present dotfile's `[policy.copies_at]`, in the rename's own transaction for
  the catalog. A dotfile it cannot rewrite is named on stderr and in `--json`, and never undoes
  the rename. It does not rewrite `config.toml`: it says so for an `[[archive_sets]]` table, and
  says nothing about `[defaults] copies_at`.

**The dotfile layer is frozen in the catalog** (item 148). A unit whose source is gone has no
dotfile to read, and is exactly the tape-only unit whose places matter. As built (the
coordinator's mechanics ruling), what is frozen is the dotfile's own map, never the resolved
one, into `units.copies_at_frozen`:
- at `snapshot create` (before the content match, so a run that mints no version still records
  edited targets), at `stage create` (after the policy resolves, so a refused dotfile never
  freezes) and at `collection sync`'s adoption of a dotfile; `collection run` freezes through
  its own snapshot and stage;
- a present dotfile's map is stored (an empty one too), a present dotfile without the key
  stores NULL, and an absent dotfile changes nothing; each change is a `copies_at_frozen` event;
- the policy reads the frozen map only while the dotfile is absent. A present dotfile always
  wins.

**The floor** (item 149). Every reader of the copy floor now takes
`max(min_copies, the map's sum)`, multiplied for a tape-only unit by `[compaction]
tape_only_safety_multiplier`, which also multiplies each per-location target (item 46's rule):
- `audit`'s `copy_count` and `restage_action`;
- the release of staging after `volume write`, `volume resume` and `collection run`, and
  `staging clean`'s retention;
- `report pending`, `report summary` and `report fire-risk`;
- `snapshot mark-reclaimable` and `report supersedable`, the retire family's Tier-2 facts
  (`volume retire`, `cartridge retire`, `volume compact-finish`), and `unit mark-tape-only`;
- `collection status`, and `--policy-aware` on `collection plan|run` and `volume plan`;
- the slices a span in progress still owes, which are judged against the floor, not
  `min_copies`.

**Changed for archive sets, for the CTO's note:** a set whose `required_locations` names more
places than its `min_copies` now has a floor of the number of names. A set with
`min_copies = 1` and `required_locations = ["home-rack", "offsite"]` needs 2 copies in all,
where 1.7.0's `copy_count` asked 1 (its `location_presence` already wanted one at each place).
So `copy_count` now fires beside `location_presence` until both are met, and the release after
a write holds staging until the second copy, where 1.7.0 released it after the first. home2 has
no archive sets (`contrib/hosts/home2.profile`), so nothing there changes.

**The per-location checks** judge the resolved map, never `required_locations` on its own:
`audit`'s `location_presence`, the Tier-2 gates of `snapshot mark-reclaimable`/`report
supersedable`, the retire family and `unit mark-tape-only`. A name a dotfile's map replaced is no
longer asked for, a count above 1 is asked for in full, and a folded name is not asked twice. The
wording is byte for byte 1.7.0's when every target is 1. A count above 1 reads, for example:
```
has 1 copy at required location offsite, needs 2 (policy requires 1 at home-rack, 2 at offsite)
```

**`report needs [--location X] [--all] [--json]`** (item 160, new). For each unit `audit` checks
(active, tape-only, missing): its copies against its copy floor, and at every location its
target, its copies there and how far short. Only units with a target, or short of the floor, are
listed unless `--all`; a unit whose policy will not resolve is always listed, with the reason.
With `--location X` it shows X alone and each unit's item-158 group there (below). An
unregistered `--location` is refused by name. It reads the catalog in four passes and resolves
each unit's policy once.

## Auto-stage for a location (#493)

**`tapectl stage for-location X --volume LABEL [--jobs N] [--device DEV]`** (item 151, new;
`--dry-run` and `--json` are honoured). LABEL is a volume initialised and not yet written:
- **Need at X** (item 158), judged for the version a write would put on tape (a new or changed
  unit's next version holds no copy anywhere, item 153): group 1, the target at X is unmet;
  group 2, short of the copy floor with no target at X and no copy at X yet. A unit holding all
  its copies at X is never picked for X.
- **Priority** (item 152): the staged sets already for X go first (they ride, and are never
  staged again). The rest follow the plan order, the owed run of a span in progress continuing
  at X, then whole units, then units that may span (item 83), and within each, group 1 before
  group 2: group 1 by the largest shortfall at X (0 copies there before 1 short) with the fewest
  copies in all breaking ties, group 2 by the fewest copies, then the name. Next-fit (item 69):
  the first unit that does not fit closes the tape, and the rest are named as waiting for the
  next tape for X.
- **Room**: the volume's capacity at the drive's fill ceiling less the end-of-tape reserve, and
  its plan bound when the drive declares `post_warning_bytes` (item 113). `--device` names the
  drive whose figures size it; no drive is touched. When what is already staged for X does not
  all fit, nothing more is planned and a warning names it.
- **Staging** (item 153): new and changed units are snapshotted and staged as `collection run`
  does; an unchanged unit's version is staged from its source. A tape-only unit's version, and a
  span in progress no longer staged, is read back with `volume read-slices`: **the command
  prints the `volume read-slices --from <LABEL>` lines, grouped by tape in the order to run them,
  and never moves a tape** (the coordinator's mechanics ruling). A unit whose source is not
  there is named and skipped.
- **A span in progress** (item 159, as built): an owed run is bound to a location only when it
  continues a range, that is, when it starts after slice 1. It then goes only onto a tape for the
  location of the tape whose range ends just before it, and for any other location it is named
  as waiting. An owed run that starts at slice 1 begins a copy of its own and is judged by its
  need like any version. **Applying the ruling, for the CTO's note:** the literal reading would
  have pinned every spanning unit with targets at two locations to its first one.
- **A warehouse** is refused (item 157): a copy there is a recorded deposit of a sealed tape. The
  refusal names `volume deposit add <LABEL> --to <warehouse>` and the sealed tapes holding a
  current version of each unit whose target there is unmet.
- The plan ends with the command to run next: `tapectl volume write LABEL --for-location X`.

**`volume write LABEL --for-location X`** (items 150 and 151, new):
- It writes only the staged sets that still have need at X, and a span whose earlier range is on
  a tape at X; the others stay staged and are named ("not for X"). With nothing staged for X it
  refuses before the drive is touched.
- Once the volume is sealed and confirmed it is moved to X, as `--move-to X` does (a copy counts
  at X only once it is there, item 150). A different `--move-to` is refused.
- The write's catalog pre-flight runs over the sets it takes.
- Plain `volume write` is unchanged: it takes every staged set, and its release is the copy
  floor.

**`--keep-staging-for-locations`** on `volume write` (item 154, new): release the staging only
once every per-location target of each unit written is met, not at its copy floor, so the next
location's tape reuses it. The output names the locations still short of each unit. A unit whose
staged data holds a range keeps every slice under it, there being no per-slice per-location
count to release by. Without the flag, staging is released at the copy floor as before, and a
later location's copy is staged again, from the source or by `read-slices`. It does not combine
with `--keep-staging`.

## Item 94's start (#492, item 147)

A spannable set larger than one tape now starts right after the owed runs (item 122's order).
1.7.0 started it as late as it could while touching the fewest tapes, with whole units before it,
so by the plan's own estimate it ended exactly at its last tape's bound and an early warning
before nominal cost one more tape. Now every whole unit is deferred on the set's first tape, and
on its last tape the set's owed run comes first and the whole units follow within item 113's
bound (item 123). Every other case is unchanged: a spannable set that fits one tape still goes
last (item 95). Planning only: no byte on tape changes, and home2 cannot reach it until staging is
larger than one tape.

**`collection plan` and `collection run`**: the whole units such a span displaces stay in its
batch while they fit after its tail on its last tape (the coordinator's ruling applying item
147). The first that does not fit closes the batch, next-fit as before. The preview says:
```
spans: larger than one tape, first on its batch's first tape, continued on the next: <unit>
after the span's tail, on its last tape (ADR-0012 item 147): <units>
```
and `--json` (plan, `run --dry-run` and `run`) carries `after_tail`. `collection run` writes
each copy through `volume write`, so the riders go on the span's last tape by the same plan; a
rider not written there stays staged and under-copied.

## #491: an envelope's size varies between builds

age writes a random "grease" stanza into every header, so two encryptions of the same envelope
to the same recipients differ by up to about 170 bytes (0-166 measured over 2000). An envelope
near a 4 KiB block boundary can land a block above or below another build's. `volume write`
validates and writes the one Layout it built, and the capacity gate's margin (one block per
generated file) bounds the drift; `CapacityNumbers::margin`'s doc now says so.
- Nine write tests bet on an envelope's size, with a budget or a one-byte edge placed inside
  that drift. Each now leaves the drift on both sides or judges the probe's own numbers
  (`CapacityNumbers::fits`), and eight have a twin that grows the envelopes by 512 to 4608 bytes
  (the positive control).
- **A real, rare false refusal is fixed.** When a span plan was built again, `volume write`
  could refuse a Layout the capacity gate accepts with "internal error … disagrees with itself",
  because a rebuild can land up to one block per file above the probe. The read-back now places
  the units on the plan's own bytes when the built files exceed the probe's by no more than the
  margin; anything else is still the internal error, and whether the Layout fits stays with the
  capacity gate. It failed safe: nothing was written.

## Catalog migration 040

Two nullable TEXT columns, added in place: `archive_sets.copies_at` (the set's map as a JSON
object; NULL defers to `[defaults]`) and `units.copies_at_frozen` (the dotfile layer's own map;
NULL when the dotfile set none, or the unit has not been snapshotted or staged with it since).
No CHECK on either, as `required_locations` has none: the policy refuses a value that does not
parse, naming the unit and the layer. Nothing to guard: no existing value or CHECK changes. There
is no downgrade past migration 040.

## Upgrading

home2 upgrades in place:
- back up the catalog with the tapectl it runs (`db backup`);
- install; migration 040 applies at the first open;
- nothing in `config.toml` needs editing, and no unit has a target until one is set.

**Run 1.7.1 before any dotfile carries `[policy.copies_at]`.** Every older tapectl refuses the key
by name, so 1.7.0 refuses to snapshot or stage a unit whose dotfile has it, and its `audit`
reports the unit `policy_unresolvable`. `copies_at` in `config.toml` is worse: an older tapectl
will not load the file at all.

**Register the locations before naming them.** A `[defaults] copies_at` that names a location
`location add` has not made passes `config check` and makes every unit that takes the `[defaults]`
map unresolvable (`audit` reports `policy_unresolvable`, and `stage create` refuses). Add the
locations first.

**A catalog rebuilt from tape** (`catalog rebuild --from-volume`) cannot restore a tape-only
unit's dotfile-layer targets: the on-tape `catalog.db` does not carry `units.copies_at_frozen`. Its
archive-set and `[defaults]` targets stay, being configuration. A unit whose source is present
takes its targets from its dotfile as before.

Nothing on tape moved, so an Heir Kit made by 1.7.0 still matches every tape 1.7.1 writes.

## Known open items

- **The full mhvtl gate and the whole tape chain on the 1.7.1 commit**, with item 147's gate leg,
  before 1.7.1 is tagged.
- **Per-location targets:**
  - `unit discover` and `collection sync`'s re-finding of a known unit do not freeze the dotfile's
    `copies_at`;
  - `archive-set edit` cannot clear a set's `copies_at` back to "defer to `[defaults]`" (as for
    every archive-set column);
  - `location rename --dry-run` does not preview the dotfiles it would rewrite, and `location
    rename` does not touch `config.toml`'s `[defaults] copies_at` or say so;
  - `report needs` judges a unit's current coverage, where `stage for-location` judges the version
    a write would put on tape, so the two can differ for a changed unit;
  - the shared-place warning of `volume write` names copies at the volume's recorded location
    when the write starts, which is not X for a `--for-location X` write until the move.
- **Auto-stage:**
  - `stage for-location` plans no whole unit after a larger-than-one-tape span's tail on its last
    tape (`collection plan` does, item 147);
  - its copy-distinctness warnings are judged against every staged set, not only those planned
    for X.
- **Collection:** the batch selector's per-tape estimate for item 147's riders ignores the tape's
  own files, so a rider can be deferred once more at write time; it fails safe (staged,
  under-copied).
- **Help texts:** `collection run`'s, `volume write`'s and `--keep-staging`'s, and `staging clean
  --force`'s and `--unit`'s still say `min_copies` where they mean the copy floor.
