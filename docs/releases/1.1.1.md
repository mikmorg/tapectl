# tapectl 1.1.1: release notes

What changed between `v1.1.0` and 1.1.1, for the person who runs tapectl. The record is
`git log v1.1.0..v1.1.1`, the issues closed on 2026-10-15, and ADR-0012's amendment of
2026-10-15 (items 57–64).

- **A patch release.** No generated on-tape byte changed: `tests/on_tape_golden.rs` is
  untouched, and dar's create command line (recorded on tape as `dar_command`) is
  byte-identical. Volumes written by 1.1.0 and 1.1.1 are the same format.
- **home2 upgrades in place.** Unlike 1.1.0 there is no fresh start. 1.1.1 adds one catalog
  migration (036, a new table; nothing existing is rebuilt), applied the first time the new
  binary opens the catalog. Take `tapectl db backup` with 1.1.0 first, as before any
  migration.

## Catalog migration 036

`cleaning_cartridges` (serial, registered, rated uses): the registry of cleaning cartridges
for `drive cleaned` (#430, item 60). `cartridges` is not rebuilt. A cleaning is an event,
and a cleaning cartridge's uses are counted from those events.

## Changes an operator will notice

### Drives

- **`tapectl drive status`** (#428) shows what is in the drive right now: loaded or empty,
  ready, write-protect, position, the drive's identity, the cartridge chip, and the catalog's
  cartridge and volumes for that serial. It never moves the tape, takes no lock and records
  nothing, so it is safe during a write. A drive held by a tapectl command is reported with
  the holder's pid and command and is sent no SCSI command.
- **`tapectl drive eject`** (#429) unloads the cartridge and records a `drive eject` contact
  and an `ejected` event. It refuses (exit 75) while a tapectl command holds the drive or a
  volume. It does not unbind the cartridge's volumes (item 61). An empty drive is exit 0.
- **`tapectl drive cleaned` / `drive cleaning-cartridge add`** (#430) record cleanings;
  `report health` shows each cleaning cartridge's uses against its rating and each drive's
  last cleaning. A spent cleaning cartridge makes `drive cleaned` exit 1.
- **Cleaning TapeAlerts read as actions** (#430) in `drive poll`, `audit` and
  `report health`: 20/21 "clean the drive: nothing is wrong with the data"; 22 "replace the
  cleaning cartridge"; 23 "not a valid cleaning cartridge".
- **`device_sg` is optional** (#431). Without the line, tapectl derives the SCSI generic
  node from `device_tape` through sysfs every time the config loads, so a `/dev/sgN`
  renumbering after a reboot never matters. `backend add --device-sg` is optional and
  `first-run.sh` step 8 no longer writes it. An explicit `device_sg` still wins and is still
  checked against the drive. An absent and underivable one is refused by name.

### Writing and initialising

- **A blank cartridge needs no `--force` when its blankness is proven** (#434, item 57):
  the chip's lifetime totals read 0 MiB written (a brand-new cartridge), or this catalog's
  own `cartridge erase` verified it and nothing was written since. `volume init` prints
  which proof it used. Every unproven tape is refused as before. `first-run.sh` step 13 no
  longer retries with `--force` after an erase.
- **`volume write` and `volume resume` release staging** (#440, item 63) once the copy they
  seal brings every unit on the volume to its `min_copies`, by the same rule as
  `collection run`, and name any unit still short. `--keep-staging` holds it, for example
  for a full verify first. `first-run.sh` step 13 passes `--keep-staging` and runs
  `staging clean` after its full verify. New `--json` keys: `staging_released`,
  `stage_sets_released`, `bytes_freed`, `under_copied`, `keep_staging`, `release_warning`.
- **The feed ratio is shown** (#439): `volume info` prints each write's native-tape bytes
  per data byte, judged against 1.05, and `report health` lists every recorded write, the
  uneven feeds first. New `--json` key `feed_ratios` on both.
- **Tape commands run at raised CPU and I/O priority** (#432, item 58). `tapectl-op` runs
  them as `sudo nice -n -10 ionice -c2 -n0 runuser -u <svc> -- tapectl …` (one password
  prompt where root sudo asks for one). `first-run.sh` raises its own shell once at the
  start of step 13, so the write, resume and verify inherit it. The drive-poll unit sets
  `Nice=` and `IOSchedulingClass=`. The profile knobs are `TAPE_NICE` (default -10) and
  `TAPE_IONICE` (default `-c2 -n0`). If sudo refuses, the command runs at normal priority
  with a notice. `home2-prep.sh` prints, and never applies, the optional vm-desk1
  `cpu_shares`/`blkiotune` lever.

### Staging

- **The source is read from disk once** (#441, closing #364's single source pass). dar
  evicted each source file's pages at open and close (`fadvise DONTNEED`), so it re-read
  from disk what the hasher had just cached. dar's archiving process now runs with that call
  made a no-op (a seccomp filter on `dar -c` only; its command line is unchanged), the hasher
  stays within 128 MiB of dar (was 1 GiB), and tapectl drops the source's pages itself once
  both have read them. On a 2 GiB fixture: 1.96x the source size read from disk before,
  1.00x after. If the kernel refuses the filter, staging carries on as before with a
  warning. Each staging job now budgets 192 MiB of memory (was 1.06 GiB), so
  `[staging] jobs` fits more jobs in the same memory.
- **Session log names are bounded** (#427): a several-unit `stage create` names its first
  unit and a count, so its session log is written (it used to fail with ENAMETOOLONG).

### Policy and audit

- **`[defaults] min_locations` is enforced after a unit is marked tape-only** (#425):
  `audit`'s new `location_count` check (a violation) and `snapshot mark-reclaimable` /
  `report supersedable` (of the superseding version) now read it, through the one predicate
  `unit mark-tape-only` uses. Tape-only units only, never multiplied (item 46).

### Operating and installing

- **A plain `tapectl status` works for the ops group** (#437, item 62). `first-run.sh`
  step 7 and `install-systemd.sh` write `/etc/tapectl/home`, naming the service home.
  tapectl reads it when the account has no `~/.tapectl` of its own. Root ignores it, and
  `--home` and `TAPECTL_HOME` override it.
- **`tapectl status` no longer calls a running session killed** on a binary whose version
  carries a comma (#433).
- **`first-run.sh -h`** no longer prints two "command not found" lines.

## Testing

- The mhvtl gate runs `mhvtl_motions` as its last leg (#416 item 12).
- The test suite runs with the home pointer switched off (`.cargo/config.toml`), so a
  `HOME`-isolated test can never reach a real service home.

## Known open items

- #416's 2 GiB performance leg inside the gate; #420, #418 R4, #388, #409.
- The home2 measurements owed by this release's issues: the next staging run's disk reads
  (#441) and a write's feed ratio before and after the priority change (#432).
