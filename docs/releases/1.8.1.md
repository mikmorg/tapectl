# tapectl 1.8.1: release notes

What changed between `v1.8.0` and 1.8.1, for the person who runs tapectl. The record is
`git log v1.8.0..` on the 1.8.1 tree, issues #502, #503, #505, #506 and #507, and ADR-0012 items
187-192, 195 and 196. No byte that tapectl writes to tape changed, and there is no catalog
migration, so by the version rule this is a patch. Almost all of it is in the scripts that
install and upgrade a host.

- **`scripts/first-run.sh --upgrade`, the in-place upgrade** (#505, item 192). From a checkout of
  a release tag, it runs thirteen steps of its own. It:
  - checks that nothing of tapectl is running, that the checkout is exactly an annotated tag,
    and that the tag is newer than the installed version;
  - backs the catalog up with the OLD binary and checks the copy, read-only;
  - keeps the old binary as `tapectl-<old>`;
  - builds and installs the new one; its first open applies the migrations;
  - runs step 14 again;
  - stops at each newer release's "Upgrading" notes;
  - runs the step-12 rehearsal and the Heir Kit again;
  - offers to tidy what earlier runs left;
  - prints the rollback.

  Running it again resumes it: a step already done is checked, not redone. `docs/install.md` §10
  is its runbook, and every release's "Upgrading" section now holds only what that release asks
  besides.
- **The rollback in `docs/install.md` §10 was wrong, and is fixed.** It put the old binary back
  and then ran its `db import`. Every tapectl command opens the catalog first, and an older
  binary refuses a catalog a newer one migrated, so after any upgrade that applied a migration
  that rollback could not run. The order now: stop the timers, import the backup with the NEW
  binary still installed, put the old binary back, `db fsck`, start the timers.
- **The rehearsal refuses a test cartridge the catalog knows** (item 192). Step 12 erases the
  cartridge it is given. It now refuses one whose chip serial, claimed serial or barcode the
  catalog records, after your consent and before anything runs, and it refuses when the
  catalog cannot be read. There is no command that removes a cartridge's row, so never erase,
  initialise or register the test cartridge through the production catalog.
- **The host remembers its profile** (#506, item 187). The first `first-run.sh` run with
  `--profile` records it in `~/.local/state/tapectl/profile`, and from then on a run without it
  refuses and names it; `--profile none` runs on the script's own defaults. A profile variable
  the script does not know is refused by name.
- **`--auto` mints no escrow identity** without `--mint-escrow` on the command line, and never
  regenerates a `config.toml` it cannot load (items 188, 189).
- **Step 12 stops `tapectl-drive-poll.timer`** for the rehearsal and starts it again however the
  step ends, so a poll never records the test cartridge in the production catalog (item 190).
- **`install-systemd.sh` never moves the catalog backup silently** (#502): over installed units
  that back up elsewhere it refuses unless `--backup-dir` (or the profile) names the directory,
  and its same-disk check follows LVM, dm-crypt and md down to the disk. A reinstall names
  each `Environment=` line of an installed unit it would drop (item 191); settings of your own
  belong in drop-ins (`sudo systemctl edit <unit>`).
- **`tapectl-op` raises five more commands to tape priority:** `volume rewrite` (#506), and
  `volume init`, `volume identify`, `catalog rebuild` and `drive eject` (item 196).
- **`volume retire`'s hint for a freed cartridge** names `cartridge erase` first and
  `cartridge mark-erased` as the fallback (#503). It is the only change to the binary.
- **Documentation** (#507): the README, `docs/install.md`, `docs/development.md` and the
  walkthrough describe any host, not the maintainer's.
- **Issues this release finishes:** #502, #503, #505, #506 and #507.

## On-tape changes

None. No golden pin moved: RESTORE.sh, MANIFEST.toml, the short seal, File 0, File 1, the front
index, the seal and the envelopes are 1.8.0's, and `requires` is computed as in 1.8.0. A 1.8.0
reader reads every tape 1.8.1 writes, and the other way round. The writer field names 1.8.1.

## Upgrading

`scripts/first-run.sh --upgrade` takes the steps every upgrade takes: the catalog backup with the
old binary, the install, the migrations, the rehearsal and the Heir Kit (`docs/install.md` §10).
What 1.8.1 asks besides:

- `--upgrade` is new in 1.8.1, and it is the 1.8.1 checkout's script that runs it, so a host on
  any earlier release that `first-run.sh` installed can use it.
- On a host with a profile, pass `--profile` on this first run of 1.8.1's script: it records the
  profile, and every later run requires it.
- Nothing in `config.toml` needs editing. Step 14 re-renders `tapectl-op` with its longer list.
- Have a test cartridge the catalog has never seen for the rehearsal.
